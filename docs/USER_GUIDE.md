# User guide

## Main menu, Scenes window and progress

The app opens on the main menu in the main window: no scene is loaded and nothing renders until you open one. Under the app's name and version, the **Start** column has **New Project** (an empty untitled project), **Open Project…**, **Open Scene File…**, **Browse Scenes…** and **Restore Last Session** (shown when an autosave exists, with its date). **Recent projects** lists up to eight project files you opened, saved or saved as, newest first, each with its folder; click one to open it. A project that is no longer where it was is removed from the list, and the status line says so ("*name* is no longer at *folder*."; on the main menu itself while the shaders compile); a project on an external or network volume that is not connected stays in the list, and the message says so. **Clear** empties the list, and **File › Open Recent** lists the same projects, adding the folder to names that occur twice, with **Clear Menu**. Below them, **User Guide** opens this guide in your web browser and **Credits and licenses…** lists the scenes' attributions. The GPU shaders compile in the background meanwhile; the first launch of a new build can take about half a minute to several minutes while the Metal compiler fills its cache, and later launches reuse it. A progress bar on the main menu shows the compilation, and an action you choose before it finishes waits with its file and starts when the shaders are ready (Cancel drops it); **Credits and licenses…** is available once they are. The menu's buttons, but **User Guide** and **Cancel**, are disabled while an action waits or an operation runs, and at the minimum window size the menu scrolls. Choosing anything other than Restore keeps the previous session as `Autosave-previous.vtrace` (open it with Open Project…), and quitting from the main menu leaves the autosave untouched.

The scene browser has its own **Scenes** window, which opens only when you ask for it: **Browse Scenes…** on the main menu, **File › Browse Scenes…** (⇧⌘O) and the inspector's **Browse…** button show it, or bring it to the front. Its close button or Esc closes it. It can be resized down to 700 × 440 and remembers its size and position. The browser lists the six built-in scenes, the five example scenes included with the app, the ten download scenes from McGuire's archive (Sponza, San Miguel, the Bistro and six smaller models) and the ten from Benedikt Bitterli's Rendering Resources (Mitsuba scenes). The filters **All**, **Built-in**, **Included** (built-in and included examples), **Downloads** and **Installed** (downloads already on disk) narrow it, and the search field matches titles, tags and credits; "No scenes match" means nothing passes both. Each card shows a preview image of the scene (bundled with the app, rendered without a denoiser; the Happy Buddha and Chinese Dragon have none and show a grey placeholder naming the format), the triangle count and format (`262 k triangles · OBJ`, or Built-in) and its state: Included, Download *size* (still to download) or Installed. The details pane beside the cards shows the selected scene's summary, triangles, materials, format, download and disk size, tags, collection with its website, credit, license link and terms, and one button: **Open** for an included or installed scene, or **Download *size*** for a download that is not installed. Above that button the pane states what it does (*Downloads 80 MB from casual-effects.com and uses … in ~/Library/Application Support/VibeTracer/Example Scenes/sponza.*), and nothing is downloaded before you click it. While a download runs the pane shows its progress bar, status line and **Cancel** in place of the button; the download continues when you select other cards, and its progress shows again when you select the card. A finished download opens the scene when the Scenes window is shown (with no dialog on it) and nothing would be discarded (no scene loaded, or a loaded scene without unsaved changes); otherwise the browser selects the scene, whose **Open** button shows, and the status line says it is downloaded. A failed download (the disk is full, or an archive does not match its expected digest) shows the error above **Download** again, and the archives that finished stay installed. Installed downloads add **Show in Finder**, and **Credits and licenses…** lists the attributions (the link appears, and **Download** is enabled, once the shaders are ready; choosing a scene before then queues it like any other action). At the minimum window size the cards and the details pane scroll. Showing or closing the Scenes window leaves a loaded scene rendering and autosave running. Opening a scene, project or file from it asks **Save / Don't Save / Cancel** first when there are unsaved changes (on the Scenes window while it is in front; Cancel keeps it open), and the window closes once the new scene is loaded, bringing the main window forward; undo, redo and **Add Model…** leave it open. If an installed scene cannot be opened (its file was deleted or is damaged), the document stays as it is, the Scenes window stays open, and the error shows in the status line and above **Open** in the details pane. A running download goes on when the window is closed.

The ReSTIR PT, reservoir-splatting and stochastic-pairwise-MIS shaders compile when a scene first needs them (ReSTIR PT right after launch, as imported scenes use it by default); until then the view renders with ReSTIR GI, reprojection and automatic neighbours, and accumulation restarts when they are ready. The spectral shaders compile the same way.

Long operations show a progress bar with their current step at the bottom left: shader compilation, opening and saving projects, restoring the autosave, OBJ import (parsing the geometry, translating MTL materials, decoding and, to fit GPU memory, downscaling textures, preparing MaterialX materials), USD import (OpenUSD composition, then mesh loading), building mesh hierarchies and hardware acceleration structures, exports and OIDN denoising. Counted steps (pipelines, textures, meshes, export samples, OIDN) show a determinate bar, the others an animated one. USD imports, exports and OIDN previews have a Cancel button there; the window stays responsive throughout.

## Inspector and navigation

### Window layout

The window has a toolbar across the top, the viewport, the inspector on the right and a status bar along the bottom. It can shrink to 700 × 440, and it opens at the size and position it had when the app last quit. The window title shows the project name (or Untitled).

- **Toolbar.** **Pause** (it reads **Resume** while paused) and **Restart** are on the left, then the **View mode** popup: Beauty, Albedo, World Normals, Depth (log) or Material / Roughness. On the right, **Export…** shows the Export tab and the sidebar button hides or shows the inspector. Opening and saving are in the File menu. Switching between Beauty and the inspection views preserves the beauty samples, including ReSTIR history; **Denoise Current Frame** needs Beauty.
- **Inspector.** The scene row and the tab bar stay at the top while the tab below them scrolls. The scene row names the current scene (a built-in scene's title, the catalog title of a scene opened from the scene browser until the project is saved or replaced, otherwise the project's name) and its **Browse…** button opens the scene browser. The tab bar has six always-visible tabs, **Render**, **Camera**, **Lighting**, **Materials**, **Objects** and **Export**, also reached with ⌘1 to ⌘6; hovering one shows its name and shortcut, and a narrow inspector shows an icon per tab instead of labels. Switching tabs scrolls to the top. Drag the inspector's left edge to resize it from 280 to 520 pt (380 pt by default); the width is remembered. ⌘E, **Export…**, the tab shortcuts and picking a surface in the viewport reveal the inspector if it is hidden, and a pick selects the surface on the Materials tab.
- **Status bar.** On the left, the render state with the progress: *Rendering · 128 / 1024 samples · 12.3 s* with a sample limit set, *Rendering · 128 samples · 12.3 s* without one; the state is Rendering, Paused or Complete. Messages replace it for five seconds, and an error also stays on the right as an indicator after the text changes: click it to read the full message. On the right, the frame rate (averaged over the last few frames), the GPU time per frame and the render size, for example *5.0 fps · 81 ms GPU · 780×740*. Nothing render-related shows on the main menu. Long operations show their progress bar at the bottom left (see above). In a narrow window the message shortens first, then the activity text, then the error indicator, while the frame figures stay whole.

### Controls

Every number in the inspector is a row with the label on the left, an editable field at the right edge and, for most, a slider underneath. Fields, popups, switches and buttons all end at the inspector's right edge. Hover a label or control for a tooltip: the longer explanations of an option are tooltips, not text in the inspector.

- **Sliders** update the render live while you drag, and one drag is one undo step. The exceptions commit when you release the knob: the Export tab's **Width** and **Height**, and, on the Objects and Materials tabs, the scene graph's transforms, MaterialX parameters and an imported light's spectrum and spot-cone rows, whose edits rebuild meshes, recompile the material or rebuild the light tables. Clicking a knob without moving it changes nothing.
- **Snapping.** A slider snaps to a step (a 1–2–5 value near 1/200 of the range unless the row has its own, such as 0.01 for most 0–1 values). Hold **Option** while dragging to turn snapping off.
- **Logarithmic sliders.** Ranges that span more than two decades use a logarithmic slider, so the low end stays usable: for example **Sun** intensity, **Sample limit**, **Time limit, seconds**, **Focus distance**, **Scale**, **UV repeat**, the export **Width**, **Height** and **Samples**. A logarithmic slider snaps to about 2% of the value.
- **Fields.** Type a value and press Return (or leave the field) to apply it. Where a row says so, typed values may go beyond the slider's range up to a larger limit (for example **Sample limit** up to 16,777,214 and **Indirect clamp** up to 100,000); otherwise a typed value is clamped to the slider's range. Whole-number rows round what you type. A decimal comma is accepted where the system locale uses it, and whitespace is ignored. Text that is not a number is refused with a message in the status bar and the field keeps its value. Fields show a value at the precision of the row's step, without trailing zeros; typed values keep their precision.
- **↑ and ↓** in a field step the value by one step, **Shift** by ten steps and **Option** by a tenth of a step.
- **Zero values have names.** A row whose zero means "none" shows a word instead: **Unlimited** for the limits, **Off** for **Indirect clamp** and the **Raw / MetalFX divider**, **Pinhole** for **Aperture radius**. You can type the word.
- **Reset buttons.** A ↺ button between the label and the field appears only while the value differs from its default, and its tooltip names the default. A three-field row such as **Translation** has one ↺ for all three fields.
- **Vector rows** put the X, Y and Z (or R, G and B) fields on one line, without sliders. **Colour rows** open the colour panel, and dragging in it is one undo step; colours are linear light, shown sRGB-encoded.
- **Switches and popups.** Every setting here is one undo step named after its label, except app preferences (the Export tab's **Format** and **Show in Finder when done**, and which sections are open), which are remembered by the app and are neither undone nor saved in the project. A popup whose longest item would not fit beside its label is shown under the label.
- **Destructive buttons** (**Delete**, **Reset Material**, **Remove MaterialX Graph**, **Remove Image**, **Reset Render Settings**) have red titles.

Display-only rows (exposure, white balance, tone map, the view mode and the **Raw / MetalFX divider**) keep the accumulated samples. Changes to them repaint immediately even while paused, complete, or showing a denoised preview, without tracing new samples; resizing or toggling the inspector while paused keeps the paused render.

### Render tab (⌘1)

**Quality**

- **Preview resolution:** the viewport's render resolution as a share of its size, 25%, 33%, 50% (the default), 67%, 75% or 100%. Lower renders faster and blurrier; exports use their own size. A project saved with another scale shows a last item **Custom (NN%)**, which changes nothing when chosen. Changing it restarts accumulation.
- **Path depth:** 16 by default, a whole number from 1 to 64 that counts path vertices as pbrt does: 1 is direct lighting only, 2 adds one bounce, and so on.
- **Sample limit:** **Unlimited** by default. The slider runs from 0 to 16,384 and a typed value up to 16,777,214 is accepted. Rendering stops at the limit and the status bar says Complete.
- **Time limit, seconds:** **Unlimited** by default; the slider runs to 3,600 s and a typed value to 86,400 s. The limit counts only time the Mac is awake.

The viewport refreshes at the display's rate (up to 120 Hz) and, once the view is still, renders as many samples per refresh as the GPU finishes in time, so faster Macs converge faster instead of waiting for the display; exports likewise keep the GPU busy between samples.

**Method**

- **Sampling strategy:** ReSTIR Direct + Indirect, Standard MIS, Light Only (NEE) or BSDF Only, with MIS, NEE and BSDF strategies as in a conventional path tracer. On imported meshes and USD scenes, ReSTIR reuses whole light paths (ReSTIR PT) between neighbouring pixels and, while the camera moves, between frames: direct light, glossy reflections, mirrors and glass all benefit, which most visibly cleans up the preview while you navigate. On the procedural scenes, ReSTIR resamples primary direct lighting and the first diffuse indirect vertex (ReSTIR GI), and deeper diffuse, glossy, and transmission paths continue through the path tracer, which is faster there; its spatial reuse can favour nearby pixels with a similar surface position and normal. For a converged reference image, Standard MIS is often as fast. When ReSTIR is chosen but the frame renders with Standard MIS (a scene with participating media, or with caustic light tracing), a line under the popup says so. MetalFX denoises only the ReSTIR strategy.
- **Light transport:** under the strategy, for every strategy. *RGB* traces red, green and blue. *Spectral* traces four wavelengths per path (Christoph Peters' method: colours become smooth reflectance spectra, `PETERS2019`, `FOURIERSRGB2019`, `PETERSBLOG2025`; light is integrated against the CIE colour-matching functions and shown as sRGB). It renders what RGB cannot: lights with a real spectrum (the Lighting tab's **Light spectrum** and **Sun spectrum**), glass that splits white light into colours (MaterialX `transmission_dispersion_*` inputs), thin-film iridescence (MaterialX `thin_film_*` inputs), and saturated colours that interreflect without RGB's errors. Scenes with RGB-coloured lights look the same in both modes apart from RGB's error in coloured interreflections, but Spectral costs roughly 25–35% more GPU time per frame and each frame shows some colour noise, which accumulation removes. *Automatic* (the default; the item reads **Automatic (currently: …)**) uses Spectral; choose *RGB* for the faster RGB renderer. Projects saved before this choice existed, or with Automatic, render spectrally. The first spectral render compiles its shaders in the background (about 3 s); until then the view renders in RGB and the tab says so. The choice is saved in the project and is one undo step that restarts accumulation; exports use it.
- **Caustics:** under the light transport, for imported scenes. *Light tracing* traces paths from the scene's emitters and its sky, HDR environment and sun (each sample, about a million; the share starting from the environment follows how much each source has contributed) through glass and polished metal, and wherever such a path reaches another surface the camera sees directly it adds that light to the pixel there; camera paths leave the same light out, so nothing is counted twice and the render stays unbiased ([docs/CAUSTICS_DESIGN.md](CAUSTICS_DESIGN.md)). It helps most with small lights behind glass: on Cornell Box 2026's caustics view it lowered the floor's error 1.6× at equal render time, for 45% more time per sample (tests/PERFORMANCE.md, "Caustic light tracing"). Glass and metal count as caustic-forming when their roughness is at most 0.1. *Light tracing + photons* also renders caustics seen through glass, water or a mirror (the floor of a pool seen through its water, a table seen through a glass), caustic light that bounces on to other surfaces, and light focused into fog or haze: the same light paths leave photons where they land or scatter, and camera paths collect the photons within a small radius at up to two surfaces or points in a medium after the first, which shrinks as samples accumulate (Knaus and Zwicker's progressive photon mapping), so such caustics are slightly blurred at first and converge to the correct image. In spectral transport the photons keep their four wavelengths, which the pixels that collect them share, so no colour passes through RGB. In a spectral scene with participating media (including glass with an absorbing interior, as in Cornell Box 2026) the photons need a shader of their own, which compiles in the background the first time; until then the scene renders with light tracing. The *guided* variants learn, as samples accumulate, which directions from each light lead to caustics the camera sees and send half the light paths there: on Glass of Water that lowered the caustics' noise 4.4× per sample but made each sample 3.6 times as long, so guiding pays only where few light paths find the glass and the rest are costly. With any of them the scene renders with Standard MIS instead of ReSTIR, as scenes with participating media do. *Automatic* (the default) and *Off* use path tracing alone; showcase shots set `"caustics"` to 1 (light tracing), 3 (with photons), 4 or 5 (the same, guided). The choice is saved in the project and is one undo step that restarts accumulation; exports use it. Its shader compiles in the background the first time.
- **Indirect clamp:** caps the luminance that one sample's indirect light can add, which removes fireflies (isolated bright pixels from rare light paths). **Off**, the default, keeps the render unbiased. Any other value is **biased**: bright indirect effects such as caustics and light scattered many times in haze lose energy, the more so the lower the cap. The slider runs from 0 to 100 and a typed value up to 100,000 is accepted. Indirect means light after two or more scattering events: mirrors and glass do not count, so direct light seen in a mirror is never clamped, and neither are lights seen by the camera. With ReSTIR PT (the default for imported scenes) the cap applies to its whole reused estimate, direct light included. Values around 10–50 times the brightness of a lit surface usually remove only the fireflies. The value is saved in the project; showcase renders set it per shot (`"indirectClamp"` in `scripts/showcase.json`) and say so in their image notes.

**Denoising**

- **MetalFX preview:** a switch, off by default, so the view shows the raw accumulation; projects saved with it on keep it. It is disabled with a note on GPUs without MetalFX. MetalFX operates at the internal render resolution, is available with ReSTIR on supported GPUs (with another strategy, or when the frame renders with Standard MIS, a note says the view shows raw samples), and maintains its own temporal history. A paused refresh never re-runs MetalFX.
- **Raw / MetalFX divider:** shown while MetalFX preview is on. **Off** (the default) shows MetalFX only; a value from 0 to 1 shows the raw accumulation left of the divider and the MetalFX result right of it. It is for preview comparison and is omitted from exports.
- **OIDN quality** (Fast, Balanced or High, the default) and **OIDN guides** (Colour only, Albedo, or Albedo + normal, the default) set Open Image Denoise's filter quality and auxiliary images for **Denoise Current Frame** and for denoised exports. Choosing the current value records nothing.
- **Denoise Current Frame** and **Clear Denoised Preview** (two buttons on one row): see Export, below. **Clear Denoised Preview** is enabled only while a denoised preview is shown.

**Advanced** (a collapsed section; the tab remembers whether it is open)

- **Sampler:** under the strategy's settings, for every strategy. *Automatic* (the default) currently uses Independent (PCG), until Z++ is re-measured after its 2026-10-04 fix for square tiles in still accumulations. *Z++ (blue-noise LD)* draws Owen-scrambled low-discrepancy samples ordered along a shuffled Z curve of the image (Ahmed, Pharr and Huang, SIGGRAPH Asia 2026; `ZPP2026`): neighbouring pixels take complementary samples, so a single frame's noise is fine-grained rather than blotchy, and every pixel's samples over a still render form a stratified set, which lowers its error at the same sample count (by 2–87% in the measured scenes, most on matte surfaces lit by the sky or an area light, least through glass) for 0.4–5% more GPU time per frame. *Independent (PCG)* draws per-pixel random numbers. The choice is saved in the project and is one undo step that restarts accumulation.
- **Light sampling:** for every strategy; it affects imported scenes' emitters only (procedural scenes, the sky and environments are unchanged). *Light tree* chooses each light sample's emitter by how much light it can send to the point being shaded, from a hierarchy over the emitters' positions, power and facing (`CONTY2018`; [docs/LIGHT_TREE_DESIGN.md](LIGHT_TREE_DESIGN.md)): distant lamps and lights facing away are rarely or never chosen, so scenes with many lights spread through a space need far fewer samples. *Power* chooses emitters in proportion to their power alone, wherever they are. Both are unbiased. *Automatic* (the default) uses Light tree. The choice is saved in the project and is one undo step that restarts accumulation; exports use it.
- **ReSTIR reuse modes:** with the strategy ReSTIR Direct + Indirect, four popups choose how it reuses samples; with the other strategies they are replaced by the line "Reuse settings apply only to ReSTIR Direct + Indirect." Each starts at **Automatic (currently: …)**, which names the mode the current scene resolves to, and hovering a popup shows its trade-off. While a mode's shaders compile, a line says that ReSTIR GI renders meanwhile.
  - **Indirect reuse:** *ReSTIR GI* (the procedural-scene default) reuses the first diffuse bounce and is fastest. *ReSTIR PT* reuses whole paths, which helps glossy reflections, mirrors, glass and deep lighting, at about 1.3–2.3× the GPU time per frame and 114–210 bytes more GPU memory per pixel. *ReSTIR PT (unified)* (the default for imported meshes and USD scenes) also samples direct light as part of those paths.
  - **Spatial neighbours:** *Uniform* taps (the procedural-scene default) or *Compatibility-guided* ones, which prefer neighbours with a similar surface: lower noise on imported meshes for 3–26% more frame time. It applies to ReSTIR DI and GI; unified ReSTIR PT pairs its own neighbours. *Stochastic pairwise MIS* reuses from a 64-pixel cell of similar surfaces, picking neighbours with the most light, and removes the bias of spatial reuse. It applies to ReSTIR DI, GI and PT. With ReSTIR PT it gives visibly less noise per sample, especially in areas the moving camera reveals, and suits final renders of imported scenes. It costs 13–55% more frame time there (5–21% with ReSTIR GI, where it does not lower noise), 44–92 B more GPU memory per pixel, and can look blotchier under the MetalFX denoiser.
  - **Temporal reuse:** *Reprojection* (the default) or *Reservoir splatting*, which lowers noise in areas revealed while the camera moves, for 5–26% more frame time and about 200 bytes more GPU memory per pixel. A still view renders identically with either mode.
  - **Path shading:** how ReSTIR PT shades a pixel. *Control variates* (the default wherever it applies: ReSTIR PT with uniform or compatibility-guided neighbours) keeps a colour estimate per pixel and refines it from neighbouring pixels and earlier frames, which mostly removes colour speckle: 5–47% less noise per frame while you navigate and 5–21% less under MetalFX, and a little less in still renders, at about the same frame time. Without the denoiser, a moving view can show a few black pixels. *Resampled* shades each pixel from its selected light path. ReSTIR GI and stochastic pairwise MIS always use resampled shading.

  The choices are saved in the project (older projects open with Automatic) and each change is one undo step that restarts accumulation. Exports use the chosen indirect reuse, neighbours and path shading; an export accumulates a still view, so it always reprojects. If a heavier mode would not fit the GPU memory budget at the current preview size, the change is refused with an error, the popup reverts, and rendering continues with the previous mode.
- **Treat guides as noisy** (on by default): Open Image Denoise cleans the albedo and normal guides, which accumulate with the samples; off, it trusts them as noise-free. **Robust HDR input scale** (off by default): off, OIDN chooses its own HDR input scale; on, the scale is keyed on the lit, non-emissive surfaces. **Diffuse firefly suppression** (on by default): keeps isolated very bright samples from spreading into false bright patches, without altering the raw samples. These three affect only OIDN output (**Denoise Current Frame** and denoised exports); they keep the samples and clear a shown denoised preview.
- **Ring boost:** an artistic, biased approximation of the ring caustic for the Reflective Ring Study's original ring position. It is listed only on that scene, or on any scene while it is on, so that it can be switched off. It restarts accumulation.

**Reset Render Settings** (the last button, red) restores every setting on this tab to its default as one undo step, and restarts accumulation: preview resolution 50%, path depth 16, both limits Unlimited, the strategy ReSTIR Direct + Indirect, the sampler, light transport, light sampling, caustics and the four reuse modes Automatic, indirect clamp Off, MetalFX preview off, the divider Off, the OIDN options and the ring boost at their defaults. It is disabled while everything is at its default. It does not touch exposure, white balance, tone map, the view mode, export settings or anything specific to the scene. If the default reuse modes would not fit the GPU memory budget, nothing changes and an error says so.

### Camera tab (⌘2)

Each scene opens at its default view (an imported USD scene at its own camera). Drag to orbit, Shift-drag to pan, scroll to zoom. A press becomes a drag only after the pointer moves 3 points; a plain click selects the surface's material/object group without editing the camera or marking the document edited. Trackpads zoom with precise deltas; notched mouse wheels are scaled 10× per line. The fields below refresh after mouse navigation (at most four times a second, and not while you are typing in one).

**Lens**

- **Field of view, °:** 5 to 150, the vertical angle. The default is the scene's own: 38° for the Architectural Pavilion, 40° for the Veach MIS Benchmark, 42° for the others, and on an imported scene the field of view of its imported camera (the saved view **USD: …**, **glTF: …** or **Mitsuba: camera**) when it has one.
- **Aperture radius:** **Pinhole** (0, the default) keeps everything in focus; up to 0.5 in scene units, larger blurs more.
- **Focus distance:** the distance to the plane in focus, which applies when the aperture is open. The slider runs from 0.01 to 1,000 (default 4.6) and a typed value from 0.0001 to 1,000,000 is accepted.
- **Focus at Camera Target** sets the focus distance to the distance between the camera and its target.

**Position**

- **Position** and **Target** are vector rows: the camera's position and the point it looks at and orbits around. Typed values may be within ±1,000,000. The fields show the coordinates on a grid scaled to the view (0.01 at a few units away), ↑ and ↓ step by that grid, and editing one field changes only that coordinate. Moving **Position** keeps the target, so the camera turns to keep looking at it; moving **Target** keeps the camera's direction and distance.
- **Reset View** returns to the scene's default view, as one undo step: a built-in scene's own camera, or, for an imported scene, the camera imported with it (the saved view named after the format, such as **USD:** *camera*, **glTF:** *camera* or **Mitsuba: camera**), or, when the file had none (an OBJ, or a USD, glTF or Mitsuba file without a camera), the default angles with every object framed, as **Frame All** does. It sets the field of view too, and never changes the aperture or the focus distance.

**Saved views**

- **Saved view:** a popup listing the project's views by name, shown when there are any. Choosing one moves the camera there.
- **Save Current View…** asks for a name (**View** *N* by default); saving under an existing name replaces that view. The new view becomes the chosen one.
- **Update**, **Rename…** and **Delete** act on the chosen view: **Update** stores the current camera in it, **Rename…** refuses a name another view already has, and **Delete** asks for no confirmation but is one undo step. The chosen view is remembered by the app; if it no longer exists, the first view by name is chosen.

**Image** (the display settings: none restarts accumulation)

- **Exposure, EV:** −16 to 16, default 0.
- **White balance, cool → warm:** −1 to 1, default 0.
- **Tone map:** Filmic fit (the default), Reinhard or Linear / clip.

They affect the viewport and PNG export; OpenEXR keeps linear radiance, without exposure or tone mapping. The viewport and PNG export use the exact sRGB curve.

### Lighting tab (⌘3)

The tab shows only the lighting the current scene reads.

| Scene | Sections |
| --- | --- |
| Architectural Pavilion | Environment, Sun, Atmosphere |
| Cornell Box, Veach MIS Benchmark, Cornell Glass & Mirror, Cornell Fog Study, Reflective Ring Study | Lights, Atmosphere |
| Imported scenes and the Imported Mesh Studio | Environment, Sun, Lights (the light spectrum only), Atmosphere |

**Environment** (sky scenes)

- **Sky preset:** Golden Hour, High Noon or Twilight / Studio. Choosing one also sets the sun's azimuth, elevation and intensity (133°, 27°, 850; 131°, 62°, 1100; 128°, 19°, 550). Shown only without an environment image.
- **Load Environment Image…** loads an equirectangular image (HDR, EXR, PNG, JPEG or TIFF) that replaces the procedural sky; the line "Image: *file name*" then replaces **Sky preset**, and **Remove Image** (red) returns to the procedural sky.
- **Brightness:** 0 to 100, default 1.
- **Rotation, °:** −180 to 180, default 0, turns the image about the vertical axis. Shown only with an image.

**Sun** (sky scenes)

- **Azimuth, °:** −180 to 180 (typed up to ±360). **Elevation, °:** −89 to 89 (typed up to ±90). **Intensity:** 0 to 10,000. Their defaults are the current sky preset's sun (Golden Hour: 133°, 27°, 850).
- With an environment image the procedural sun has no effect, so **Sun** appears only when the scene has an imported distant light (the line "Imported distant light: *angle*° sun." says so); its intensity is then irradiance at normal incidence, independent of the environment brightness, and choosing a sky preset restores the procedural sun.
- **Sun spectrum** chooses a CIE illuminant for spectral light transport (below).

**Lights**

- On the finite-light scenes: **Intensity** (0 to 100, default 1) and **Size** (0.05 to 4, default 1) multiply the emission and size of the scene's lights, and **Light colour** tints them (linear RGB). The Veach scene's four lights share these settings. **Light spectrum** is described below.
- On imported scenes only **Light spectrum** is here; each imported light has its own controls on the Materials tab.
- **Light spectrum** (area and sphere lights and imported emitters) and **Sun spectrum** choose a CIE illuminant for spectral light transport: E (equal energy), D65 (daylight), A (incandescent, 2856 K), FL11 (narrow-band fluorescent), HP1 (high-pressure sodium) or LED-B3 (white LED). *RGB colour* (the default) gives a daylight-shaped spectrum with the light's RGB colour, which looks the same as RGB transport. Presets need spectral light transport (the default); the light colour then filters the preset like a coloured gel, and the intensity keeps its luminance. Narrow-band light (sodium, fluorescent) shifts colours the way real lamps do, which RGB cannot reproduce. RGB transport ignores the presets. The sky and environment images stay RGB.

**Atmosphere** (every scene)

- **Atmosphere:** Clear, Fog preview (a fast single-scatter camera fog) or Participating medium, which fills the scene's bounding box with homogeneous haze. Its controls: **Density, 1/m** is the extinction per metre (slider 0 to 5, default 0.05, typed up to 100); **Scattering albedo** the fraction scattered rather than absorbed, as a colour; **Anisotropy** the Henyey–Greenstein g from −0.99 to 0.99 (positive values scatter forward, so beams glow when you look along them); and **Scattering law**, *Grey* or *Rayleigh (λ⁻⁴)*, which makes short wavelengths scatter more, so beams turn orange as they cross it. Media render with Standard MIS: when the strategy is ReSTIR, the Render tab says so. Imported objects carry their own media with OpenPBR `transmission_depth`, `transmission_scatter` and `transmission_scatter_anisotropy`; a surface with `specular_weight` 0 is an invisible container, and the USD attribute `vibe:medium:rayleigh` on its material makes it scatter by the Rayleigh law. See [docs/VOLUME_DESIGN.md](VOLUME_DESIGN.md).

### Materials tab (⌘4)

**Selection.** The **Object** popup chooses what to edit. A built-in scene lists the surface groups it uses (for the Cornell Box and Cornell Fog Study: Room surfaces, Tall box and Short box; the Veach scene: Floor and Plate 1 to 4; the Architectural Pavilion: Architecture, Floor, Copper sphere, Gold ring, Chrome sphere, Glass sphere and Plinth). An imported scene lists **Studio floor** and then its hierarchy, indented by depth, groups marked ▸ and meshes ◇. With a mesh selected, **Subset** chooses one of its face subsets and **Assigned material** the material of that subset; with a group selected, **Material** chooses any material of the scene to edit. **New Material** adds a material (and assigns it to the selected subset), and **Remove Unused Materials**, shown while some material is unused, removes the materials no object uses: deleting objects keeps materials that are no longer assigned until you do. Material edits apply to every subset assigned to the same material.

**Surface** (the built-in slots and imported materials that are not MaterialX graphs)

- **Preset:** Original scene material, Plastic, Copper, Coated metal, Fabric, Rough glass or Custom OpenPBR. Any edit below switches to Custom OpenPBR.
- **Tint:** multiplies the base colour map. **Roughness** (0.03 to 1, default 0.3), **Metalness**, **Coat**, **Anisotropy** and **Fuzz** (0 to 1, default 0), **IOR** (1.01 to 2.5, default 1.5) and **Transmission** (0 to 1, default 0).

**Texture mapping:** **Normal strength** (0 to 4, default 1), **UV repeat** (0.01 to 100, default 1), **UV offset U** and **UV offset V** (−10 to 10, default 0) and **UV rotation, °** (−180 to 180, default 0). UV repeat/offset/rotation and normal strength can be edited independently.

**Textures:** one block each for **Base color**, **Roughness**, **Metalness** and **Normal**, showing the file name (or None) and a thumbnail while a map is loaded, with **Load…** and **Clear**. Roughness and Metalness have a **Channel** popup (Red, Green, Blue, Alpha) for packed maps. See "Projects and materials" below for how the maps are read.

**Material file:** **Save Preset…** and **Load Preset…** (`.vmat`), **Import MaterialX…** (see MaterialX materials), **MaterialX Import Report…** while there is a report, and, last, **Reset Material** (red), which restores the default surface settings and removes the four maps.

**MaterialX graph.** A material that came from a MaterialX graph shows, instead of Surface, Texture mapping and Textures, a line naming the material with its number of expressions and images, and one row per constant graph input; **Remove MaterialX Graph** (red) ends the Material file section. A parameter is named by the shortest trailing part of its MaterialX path that is unique among the material's parameters (`Paint/base_color` is **Base color**, `Graph/tint` is **Tint**); generic port names (`value`, `in`, `in1` to `in4`, `fg`, `bg`, `mix`, `low`, `high`, `amount`, `default`, `input`) keep their node name (`Graph/blend/fg` is **Blend › fg**); underscores become spaces and `ior` reads **IOR**. The tooltip shows the full path. Three-component inputs are one vector row with R, G and B fields when the port name contains *color*, *colour*, *tint* or *albedo*, and X, Y and Z otherwise; scalars are number rows, and two- and four-component inputs are rows named *Name* X and Y, or R, G, B and A. An input whose value and default lie in 0 to 1 gets a 0 to 1 slider, the others a slider from −10 to 10 (widened to include the value); typed values may go to the wider of ±10 and the value. An edit commits when you release the slider or press Return, recompiles the material and is one undo step; reset restores the imported default.

**Imported lights.** A USD rectangular, disk or sphere light shows **Light** controls: **Radiance** (R, G, B, linear; slider to 1,000, typed up to 1e8; move and rotate the light on the Objects tab) and **Spectrum**, then **Spot cone** controls. (glTF, Mitsuba and OBJ emitters are MaterialX emission and show the MaterialX graph instead.) Each light has its own **Spectrum**: the scene's light spectrum, a CIE preset, a *Blackbody* temperature (**Temperature, K**, 1,000 to 12,000, default 2,700, typed 500 to 40,000) or a *Narrow band (laser)* (**Centre, nm**, 380 to 780, default 532, typed 360 to 830, and **Band width, nm**, 1 to 50, default 2, typed 0.5 to 200, the full width at half maximum), normalised to the same luminance, so its radiance keeps its brightness. **Cone angle, °** (0.5 to 90; 90, the default, is no cone), **Cone softness** (0 to 1) and **Focus** (0 to 50) shape it into a spot (UsdLux `ShapingAPI`; a few degrees make a beam). From USD, `colorTemperature` imports as a blackbody, `ShapingAPI` as the cone, and the custom attributes `vibe:spectrum` (`E`, `D65`, `A`, `FL11`, `HP1`, `LED-B3`, `blackbody`, `narrowband`), `vibe:spectrum:temperature`, `vibe:spectrum:center` and `vibe:spectrum:fwhm` choose the spectrum.

Numeric fields accept the system locale's decimal separator and surrounding whitespace; invalid text reverts to the previous value.

## Projects and materials

`.vtrace` projects embed texture bytes, the environment image, mesh assets, stable scene-node/material IDs, parent transforms, face bindings, MaterialX expression programs, per-scene state, camera, render controls, and saved views. They do not depend on original asset paths. Projects are saved in format 4: embedded images, the environment and meshes are stored once each, in an asset table inside the file keyed by SHA-256 content hashes, and mesh triangles are stored as binary data. Version 1–3 projects remain readable and are saved as format 4 (see below); a version 1 project's single imported mesh migrates when another OBJ is appended. `.vmat` presets use the same format. Version and value validation runs before loading, and failed asset decoding preserves the active project. `.vmat` presets carry one material, including its MaterialX program/images when present, or manual maps and UV/channel settings. Undo/Redo restores project edits (up to 40 actions); render samples and pause state are not project edits. Undoing a display-only or camera-only edit keeps the accumulated samples and the OIDN preview. Undoing Open also restores the previous file association, so the next Save cannot overwrite the opened file. Failed operations add no undo step.

Changes autosave after a one-second debounce (five seconds for camera-only changes) and on normal quit to `~/Library/Application Support/VibeTracer/Autosave.vtrace`. Pending autosaves coalesce to the newest snapshot, and an unchanged revision is not rewritten. An autosave keeps its images and meshes as separate files in `~/Library/Application Support/VibeTracer/AutosaveAssets/`, named by their SHA-256 hash and written once, so a new revision writes the small `Autosave.vtrace` plus only payloads not stored yet. After each successful write, stored payloads that no recovery file references are deleted once they are more than ten minutes old. Recovery copies (`Autosave-previous.vtrace`, `Autosave-unrestorable-<date>.vtrace`) need that folder beside them: to move one elsewhere, copy `AutosaveAssets` along with it, or open it and use Save As, which writes a self-contained project. Quit waits for pending autosaves and explicit saves, then flushes the final state; a failed final write offers Cancel Quit. **Restore Last Session** on the main menu reopens the last autosave with its project file association and edited state; it is no longer restored automatically. An autosave that cannot be restored is moved aside as `Autosave-unrestorable-<date>.vtrace` and never overwritten. Explicit project saves are atomic and remain separate from the recovery file.

Open, New and Open Scene File ask **Save / Don't Save / Cancel** when the document has unsaved changes. With Don't Save, the replaced document is kept only as the recovery copy `Autosave-previous.vtrace`. While a project opens or saves, other project commands, inspector popups and camera gestures are unavailable. Undo, redo, scene switches and imports prepare their resources off the main thread and reuse unchanged GPU resources; exports reuse the preview's textures, hierarchies and acceleration structures instead of rebuilding them.

Projects hold at most 1 GiB of embedded images (maps, MaterialX images and the environment) across all scenes, with identical images counted once, and a project file is limited to about 4.9 GiB. Decoded textures must also fit the GPU texture budget, a quarter of the GPU's recommended working set (about 2.7 GB on a 16 GB Mac); a compressed image can need several times its file size once decoded with mipmaps. When MaterialX images (including OBJ, MTL and USD textures) exceed it, the largest are shown at reduced resolution until the scene fits, and the status bar says so; the project keeps the full-size images, so a Mac with more GPU memory shows them in full. Since project format 4, scene-graph meshes are stored indexed (about 32 bytes per triangle, a quarter of format 3); format 1–3 projects open and are saved as format 4, and builds from before format 4 cannot open it. Save refuses a project that would exceed what Open accepts and explains what to reduce.

Base-color images decode as sRGB and multiply tint; 16-bit and grayscale images decode correctly, and gray images sample as gray in every channel. Roughness and metalness maps use linear data and replace scalar values; select R/G/B/A for packed maps. Tangent-space normals use +Y (green toward the image top) like MaterialX, remain linear, perturb the interpolated shading normal, and agree on both sides of a surface. **Clear** restores the scalar parameter's effect. Maps use repeat wrapping, mipmaps (each level the area average of the one above, in linear light, whatever the image's size; a KTX file's own levels are kept), and an approximate ray-cone footprint, and are evaluated at primary and secondary hits. UV repeat/offset/rotation and normal strength can be edited independently.

**Original scene material** preserves its original type while allowing maps. A roughness or metalness map promotes it to OpenPBR with scalars that match the inspector: a matte surface takes the inspector roughness, glass stays transmissive, and a mirror stays metallic. A mirror with only a roughness map keeps its legacy glossy lobe and takes the map's roughness. Editing surface parameters or tint also creates a custom OpenPBR surface. Original ideal mirrors/glass otherwise retain their delta behavior; new rough surfaces have a roughness floor of 0.03. The finite-light colour well shows sRGB and stores linear light colour. Volumetric absorption, subsurface scattering (including thin-walled translucency, which MaterialX and USD materials can author), opacity, UDIMs, and displacement remain outside the exposed material model. Dispersion and thin films come only from MaterialX constants (see MaterialX materials) and render only with spectral light transport.

## OpenUSD scenes

Choose **Open Scene File…** (File menu and main menu) for `.usd`, `.usda`, `.usdc`, or `.usdz` (glTF, Mitsuba and OBJ files open the same way; see glTF scenes, Mitsuba scenes and OBJ below). A USD file opens as a complete scene, including supported lighting and cameras, and replaces the current imported content. It composes references, payloads, and selected variants with the official SDK at the stage’s start time. Cancel leaves the active scene intact. An import is stopped after five minutes; time the Mac spends asleep does not count. The report lists fallbacks and unsupported features and remains available as **Import Report…** on the Objects tab. Save as `.vtrace` to embed meshes, material images, matrices, lights, and the report for portable reopening; Undo restores the previous project.

Supported: polygon meshes (including concave faces), `Sphere`, `Cube` and `Cylinder` prims (tessellated from their schema attributes), indexed UV0/normals, material face subsets, hierarchy, shared mesh assets, nonuniform/mirrored transforms, stage units/up-axis, visibility, perspective cameras as saved views, rectangular, disk and sphere area lights (disks and spheres as equal-area polygons), one textured or constant-color dome (turned about its vertical axis as the stage says, shown as **Rotation, °** on the Lighting tab), and one distant light. A stage without any supported light is shown under a neutral procedural sky for inspection (reported), unless its materials emit: emissive materials then light the scene alone. The distant light is an independent sun with its authored angle. Its brightness follows the UsdLux definition: an unnormalized light's irradiance is intensity × 2^exposure × π·sin²(angle/2), so a default unnormalized sun is dimmer than in earlier versions. Degenerate faces are dropped and placeholder meshes skipped, with report lines. A camera's focus distance is used only when authored; otherwise the orbit pivot is the first surface on the view ray. Opening a USD scene starts an untitled document without the previous project's saved views. PreviewSurface’s metallic workflow and supported direct MaterialX UsdShade nodes map to the existing bounded OpenPBR evaluator. Area-light radiance is editable on the Materials tab. Original imported matrices are retained beneath the inspector’s local transform adjustments.

This is snapshot import, not full USD round-trip editing. Subdivision uses control cages; point instancers, skinned animation, volumes/curves, arbitrary shader networks, USD export, and external `.mtlx` Sdf composition are not implemented. OCIO/ACES color management, camera roll/lens shift, and some light features are not represented. The importer reports approximations; PreviewSurface-to-OpenPBR shading is not an exact BSDF match. Limits are 65,535 nodes, 1,016 imported materials, 16,000,000 stored triangles and 64,000,000 rendered triangles; identical meshes are imported once and rendered as instances. See [OpenUSD coverage and reference scenes](../Examples/OpenUSD/README.md).

## glTF scenes

**Open Scene File…** (the File menu and the main menu) also opens glTF 2.0 files: `.gltf` with embedded (data URI) or external buffers and images, and binary `.glb`. Like a USD stage, the file opens as a complete untitled scene with its import report. It is read in the app itself, without the OpenUSD helper, so even large files open in seconds. A file whose `asset.version` is not 2.0 but whose content is glTF 2.0 opens with a report line; a file that lists an unsupported extension in `extensionsRequired` (for example Draco or meshopt compression) is refused with its name.

Supported: the default scene's node hierarchy with TRS or matrix transforms, meshes shared between nodes, triangle, strip and fan primitives (each primitive is a material subset; points and lines are skipped and reported), indexed or unindexed geometry, normals (face normals when absent), `TEXCOORD_0`, sparse accessors and quantized attributes (`KHR_mesh_quantization`), embedded PNG, JPEG and WebP images (`EXT_texture_webp`), perspective cameras as saved views named **glTF:** and the camera's name (the first one opens), and one directional `KHR_lights_punctual` light as the sun (its illuminance in lux as the sun's irradiance). A file without lights or emissive materials opens under the neutral sky; emissive materials otherwise light it alone. glTF has no environment: load one with **Load Environment Image…** on the Lighting tab.

Materials become OpenPBR MaterialX graphs: base colour (factor × sRGB texture), metalness and roughness (the B and G channels of `metallicRoughnessTexture` × factors), the normal map and its scale, emission (`emissiveFactor` × texture × `KHR_materials_emissive_strength`, in nits as in glTF), `alphaMode` MASK (coverage at `alphaCutoff`) and BLEND (alpha as coverage), texture transforms (`KHR_texture_transform`), and clamp or repeat wrapping. Extensions: `KHR_materials_ior`, `_transmission` (a constant base colour tints transmitted light), `_volume` (`thicknessFactor` 0 is a thin wall; otherwise `attenuationColor` and `attenuationDistance` absorb inside the object, as OpenPBR `transmission_color` and `transmission_depth`, and do not also tint the surfaces), `_specular` (`specularColorFactor` constant), `_clearcoat`, `_sheen` (as OpenPBR fuzz of weight max(`sheenColorFactor`); fuzz's colour and roughness keep their defaults), `_anisotropy` (strength and rotation, converted exactly to OpenPBR's roughness and anisotropy, per texel when roughness is textured), `_iridescence` (a thin film of the maximum thickness and the film IOR; spectral transport), `_dispersion` and `_unlit` (rendered as emission of the base colour). The report lists what is approximated or ignored: occlusion maps (a path tracer computes occlusion), a second UV set (read from the first), mirrored-repeat wrapping (rendered as repeat), anisotropy and iridescence textures, specular-colour and clearcoat-normal textures, point and spot lights, orthographic cameras, skins, morph targets and animation, KTX2 textures and any other extension.

## Mitsuba scenes

**Open Scene File…** also opens Mitsuba scene files: an `.xml` file whose root element is `<scene>`, in Mitsuba 3's format or Mitsuba 0.6's (whose camelCase property names, such as `toWorld` and `intIOR`, and gamma-encoded `<srgb>` colours are converted). The file is read in the app itself and opens as a complete untitled scene with its import report; an `.xml` file that is not a Mitsuba scene is refused with an error and the current document is kept. Ten of Bitterli's scenes are also in the scene browser's **Downloads** (below), which open through this importer.

Read: `<default>` values and `$variables`, `<include>`, `<ref>` ids and `<transform>` (matrix, translate, rotate, scale, lookat); `obj`, `ply`, `serialized`, `rectangle`, `disk`, `cube` and `sphere` shapes, each one object named by its id (`face_normals` and `flip_normals` apply); the BSDFs `diffuse`, `plastic`, `roughplastic`, `conductor`, `roughconductor`, `dielectric`, `roughdielectric`, `thindielectric`, `principledthin`, `twosided`, `mask`, `bumpmap` and `normalmap` with `bitmap` and `checkerboard` textures, as OpenPBR MaterialX (shapes that reference one BSDF share its material); `area` emitters as emission of their radiance; and a `homogeneous` interior medium that only absorbs, behind glass. The first `perspective` or `thinlens` sensor becomes the saved view **Mitsuba: camera** and the camera the scene opens with: its field of view from `fov` and `fov_axis` (or `focal_length`) and the film, and a thin lens's `aperture_radius` (up to 0.5) and `focus_distance` as **Aperture radius** and **Focus distance** on the Camera tab. The film's `width` and `height` set the Export tab's **Width** and **Height** (16 to 8,192), and the integrator's `max_depth` sets **Path depth** on the Render tab to `max_depth` − 1 (64 for −1 or none). An `envmap` emitter becomes the environment (its image, `scale` as the Lighting tab's **Brightness** up to 100, and its turn about the vertical axis as **Rotation, °**), and a `constant` emitter a uniform environment of its radiance.

Reported in the import report and skipped: other emitters (`point`, `spot`, `directional` and others), other sensors and any after the first, media other than an absorbing interior, `shapegroup` and `instance`, a shape's `to_uv`, a texture's `to_uv` offset and rotation (only its scale is used, as Mitsuba samples the image at the scaled coordinates), and BSDFs, textures and properties the mapping does not read (with what is used instead); Beckmann microfacet distributions render as GGX at the same alpha. A scene without a supported emitter renders black, as Mitsuba renders it without them: no neutral sky is added. The orbit camera has no roll, so a rolled sensor is reported, as is a mirroring one. A dielectric whose `int_ior` / `ext_ior` is below 1 (air bubbles inside ice, say), also inside a `twosided`, `mask`, `bumpmap` or `normalmap`, is imported as its inverse from its other side, since the app's IOR is at least 1.01: the shape's facing is reversed and the report says so ("int_ior / ext_ior … is below 1; rendered as … with the shape's facing reversed"). An absorbing interior medium on such a shape is dropped and reported, since reversed it would lie outside the shape. A shape that also has an area emitter keeps its facing, so that it still emits on Mitsuba's side, and its glass is rendered index-matched ("… rendered index-matched, so that the shape's emitter keeps its side"). A `thindielectric` below 1 takes the inverse ratio, which loses the total internal reflection Mitsuba's pane has beyond its critical angle, and is reported as an approximation. An `area` emitter inside glass (a `dielectric` or `roughdielectric` shape around it, such as Little Lamp's bulb, also one open at a small gap) has its radiance divided by the square of that glass's `int_ior` / `ext_ior` (for each layer of glass its light leaves; glass with `flip_normals` around it multiplies instead, and a hollow shell around it cancels out), and the report says so ("area emitter inside dielectric '…' …; radiance divided by …"): Mitsuba's emitter radiance is the radiance inside the glass, the app's the radiance seen outside it, so the light comes out as bright as in Mitsuba. This conversion is made once, when the file is opened: if you later change the glass's IOR, move the emitter out of it or delete the glass, the emitter keeps the divided emission, so it no longer matches Mitsuba's; editing the glass in the scene file and opening it again converts it afresh. Glass that surrounds an emitter only in part (fewer than 90% of the test rays from it cross the glass the same way) is reported and the emitter is not converted. A textured conductor `specular_reflectance` that is grey (every texel's channels within 2 of 255 levels, so a grey JPEG counts) becomes a connected specular weight, as in Mitsuba; a coloured one is approximated (it scales the metal's base colour only) and reported ("coloured specular_reflectance texture scales F0 only"), and so is one that cannot be checked because it cannot be decoded or is above 64 megapixels, with a line naming the reason. A film crop (`crop_offset_x`, `crop_offset_y`, `crop_width`, `crop_height`), a sensor's `principal_point_offset_x` or `_y` and a `near_clip` other than Mitsuba's 0.01 are reported and ignored: the full frame is rendered. BSDFs that are one-sided in Mitsuba (those of `diffuse`, the plastics and the conductors without a `twosided` around them are black from the back, and so is the default diffuse of a shape without a BSDF that does not emit) render two-sided here, and the report says so once. An anisotropic `alpha_u` and `alpha_v` render isotropic at their geometric mean, a plastic or `principledthin` IOR ratio below 1 renders at its inverse (the same reflectance head-on, without Mitsuba's total reflection at grazing angles), a sphere under a non-uniform scale is an ellipsoid, and a shape or sensor whose `to_world` cannot be inverted is skipped (the sensor: the default camera stays, also when its axes are too unequal to normalize), each with a report line.

A scene file that exceeds a safety limit is refused with an error and nothing is imported: XML that does not parse, or that declares entities in a DOCTYPE (Mitsuba scenes declare none), elements nested more than 128 deep (counting through includes and references), references that lead through more than 64 definitions, includes more than 15 files deep or more than 1,024 includes in all, more than 16 `twosided`, `mask`, `bumpmap` or `normalmap` wrappers around one BSDF, a value that expands beyond 1 MiB through `$variables` or more than 64 MiB of variable values substituted in all, a bitmap above 64 megapixels that would be baked into a texture, mesh files that declare more vertices or faces than they hold or the app can address, or meshes that together pass 2^30 triangles or a quarter of the Mac's memory. Bitterli's scenes are far below these limits.

## MaterialX materials

A small walkthrough is included in [Examples/MaterialX](../Examples/MaterialX/README.md).

On the Materials tab, use **Import MaterialX…** (also in the File menu, or drop a `.mtlx` file on the window) to load a self-contained `.mtlx` document. On an imported mesh, supported materials enter the scene library and the first is assigned to the selected face subset. On a procedural surface, the first supported material replaces that slot. The import report lists rejected materials and ignored look assignments. Select a mesh child to change its subset bindings; edits to a shared material affect every assignment.

This is a bounded local importer/evaluator, not the MaterialX SDK or a visual node editor. It accepts 1.38/1.39 XML and the `open_pbr_surface` model. Supported nodes are `constant`, `texcoord` (UV0), `image`, `multiply`, `add`, `subtract`, `mix`, `clamp`, scalar `extract`, `normalmap`, `rotate2d` (constant degrees), and matching-width/scalar-broadcast `convert`. Nodegraph outputs and interface inputs resolve into the same program. Authored constants and default surface inputs are editable in the inspector; graph structure remains imported. Reset buttons restore the persisted imported default. Graph parameters use linear values.

Images use local paths at import, then embed their bytes. Images must be regular files of at most 128 MiB (1 GiB per document); paths outside the document's folder are accepted but reported, because the image is embedded. Documents must be UTF-8 or ASCII XML of at most 16 MB, and syntax errors report their line and column. Supported color spaces are linear/lin_rec709/raw/none and srgb/srgb_texture; a colorspace applies only to color3/color4 images and is ignored, with a report line, on float and vector images. `rotate2d` follows MaterialX 1.39: a positive angle rotates clockwise, the opposite of earlier versions. Images use periodic or clamp (clamp-to-edge) addressing per axis and linear/mipmap filtering; `constant` and `mirror` addressing are rejected. An `image` with no file evaluates to its `default` input (zero when unauthored), as MaterialX specifies for an unresolvable file, and the report notes it. UV arithmetic can tile/offset coordinates; `place2d`, additional UV sets, UDIMs, procedural noise, custom definitions, XInclude, OCIO transforms, and look assignment rules are unsupported. Missing images and unsupported connected nodes reject the affected material. Each material supports up to 64 instructions, with 4,096 graph images total.

Mapped OpenPBR inputs are base color/weight/metalness, specular roughness/weight/IOR/anisotropy, coat weight/roughness, fuzz weight, transmission weight and colour (`transmission_color`, constant), `geometry_thin_walled` (constant), thin-walled translucency (below), an interior medium from constant `transmission_depth`, `transmission_scatter` and `transmission_scatter_anisotropy` (see [docs/VOLUME_DESIGN.md](VOLUME_DESIGN.md)), surface normal, emission (`emission_color` × `emission_luminance`, in nits; constant, textured or computed by the graph), and `geometry_opacity`, rendered as coverage (stochastic transparency): camera, bounce and shadow rays pass a surface with probability 1 − opacity, so 0 cuts it out and partial values converge to a see-through surface. A material with `geometry_opacity` reads its images at full resolution, as the coverage is read, so the colour of cut-out texels (often white or black around foliage) never blends into the visible ones. USD PreviewSurface `opacity` maps to it; `opacityThreshold` is not applied. The renderer retains its roughness floor (0.03), IOR range (1.01–2.5), and 0–1 color/weight limits. Other authored surface inputs must be recognized default values: on solid surfaces, subsurface color/radius/radius scale/scatter anisotropy at their specification defaults, and valueless `geometry_tangent`, `geometry_coat_normal` and `geometry_coat_tangent` (their geometric defaults) are accepted. `geometry_tangent` may also connect to the world `tangent` rotated about the world `normal` by a constant `rotate3d` amount (optionally through `normalize`), as MaterialX's `gltf_pbr` writes `anisotropy_rotation`: it turns the anisotropy direction by that angle (a positive `rotate3d` amount turns clockwise, toward −bitangent). `normalmap` accepts tangent space and rejects object space. Dispersion (`transmission_dispersion_scale`, `transmission_dispersion_abbe_number`) and thin film (`thin_film_weight`, `thin_film_thickness` in micrometres, `thin_film_ior`) accept constant values; they render only with spectral light transport, the default (RGB transport ignores them). Glass with dispersion splits light into colours. Dispersive glass continues each path at one of its four wavelengths, so it converges more slowly than clear glass (spectral multiple importance sampling for rough dispersive glass is experimental and off by default). Thin films also colour ideal mirrors. A constant `specular_color` tints a metal's edge (its 82-degree Fresnel) and a dielectric's specular reflection. Subsurface on a solid surface (volumetric subsurface scattering), and connected medium, subsurface-anisotropy, transmission-colour, dispersion, thin-film or specular-colour inputs, are rejected.

**Thin-walled translucency.** On a surface with `geometry_thin_walled` true, `subsurface_weight` and `subsurface_color` (constant or connected, e.g. a leaf texture) make the surface a sheet of dense scattering material, as in the OpenPBR specification's thin-walled mode: a `subsurface_weight` share of the dielectric base scatters `subsurface_color`, half of it diffusely through to the other side and half back. A constant `subsurface_scatter_anisotropy` g from −1 to 1 moves the split: (1 + g) / 2 is transmitted, so 1 transmits everything and −1 nothing. Paper lampshades, curtains, blinds and leaves then glow when lit from behind, with every strategy and in both light transports. `subsurface_radius` and `subsurface_radius_scale` have no effect on thin walls and are accepted as constants. This matches Mitsuba 3's `principledthin` with `diff_trans` and Blender's thin-walled Principled BSDF; the Mitsuba importer maps `principledthin` to it (`REFERENCES.md` `MITSUBA3`). `transmission_weight` takes precedence over subsurface, as the specification mixes them.

Emissive materials glow from their front face (the authored winding; surfaces are not thin-walled), still reflect light, and are dimmed toward grazing angles by a coat (MaterialX's coat factor; fuzz does not dim them). Emission is in the same units as imported USD light intensities and may exceed 1 (up to 1e8). On imported meshes an emissive MaterialX material also lights the scene through light sampling: each light sample and each ray that reaches the surface evaluates the graph at that point. The sampler divides its effort between emitters with an estimate that treats every image as white, so a mostly black emission texture renders correctly but may need more samples. On the procedural surfaces emission is only found by BSDF sampling and converges more slowly. `standard_surface` emission is not imported, because only `open_pbr_surface` is supported. No `.mtlx` graph export is implemented. `REFERENCES.md` documents the implementation and adaptations.

## Meshes, environments, and export

**Open Scene File…** opens an `.obj` as a new untitled scene framed to the model, and **Add Model…** (on the Objects tab and in the File menu) appends one to the current scene. OBJ import reads positions, optional UVs/normals (including one-component `vt u` lines), positive and negative indices, backslash line continuations, and convex polygon faces (fan triangulation). Only numerically collinear faces are skipped, and their count is reported; errors name the line. OBJ import is prepared off the main thread and fails early if it would exceed 65,535 scene nodes. Missing normals use face normals. Each mesh asset is stored once, with its own acceleration structure, and every visible object is an instance of it; a small top level over the instances is rebuilt when objects move, hide or show, so these edits and material assignments do not rebuild mesh hierarchies (a changed mesh rebuilds only itself). Where the GPU supports ray tracing and a check at launch finds Metal's intersector watertight on shared edges (it is on Apple M4 with macOS 27), rays use the hardware; otherwise the renderer's own watertight 4-wide hierarchy traverses them. Either way this covers shadows, reflections, transmission, picking, and denoiser guide rays, and rays aimed at shared edges and vertices do not slip between triangles. Adding a model opens Mesh Studio, appends assets, and frames the new import. `o` and `g` become parent/mesh nodes; `usemtl` creates face subsets with named materials. Select a mesh on the Objects tab or click it in the viewport, then choose a subset and material on the Materials tab. Instances share geometry and initially share materials; assignments can be changed per instance. Parent visibility is inherited, and reparenting preserves local transform values. Materials come from the OBJ's `mtllib` files: each `usemtl` subset gets an OpenPBR MaterialX graph from `Kd`/`map_Kd` (base colour), `Ks`/`map_Ks` and `Ni` (specular weight and IOR), `Ns` (roughness), `d`/`Tr`/`map_d` or the diffuse texture's alpha (opacity), `Ke`/`map_Ke` (emission), and `map_bump`/`bump` (height maps become normal maps; normal maps stored there are recognized) or `norm`. Glass models (`illum` 4, 6, 7, 9) and glass written as dissolve (an untextured material, or a textured one named glass; other textured dissolve, such as a paper lampshade, is partial coverage) transmit 1 − `Tf`, as McGuire's archive and 3DS Max write it, so `Tf 1 1 1` is opaque. Reflection models (`illum` 3, 5, 8, and 4, 6, 7 when `Tf` makes them opaque) whose `Ks` is stronger than glass can reflect render as metal of that strength, so mirrors mirror and brass looks like brass. A `map_Kd` beside `Kd 0 0 0`, which exporters write for a texture-driven colour, is used on its own rather than multiplied to black. Map options `-s`, `-o`, `-clamp`, `-bm`, `-mm` (base and gain) and `-imfchan` apply. Textures are embedded in the project (see the image limits under projects). Statements and options without an OpenPBR equivalent (other `illum` models, `-t`, `-cc` and others), missing textures and malformed lines are listed in **Import Report…** on the Objects tab. Curves, vertex colors, and animation are not imported. OBJ files are memory-mapped and streamed, so multi-gigabyte files import within the triangle limit. Triangulate concave polygons before import. Limits are 65,535 scene nodes (so 65,535 instances), 1,016 imported materials plus eight procedural slots, stored and rendered triangles bounded by the Mac's GPU memory (about 16 million stored triangles on a 16 GB Mac, more on larger ones; the flat reference traversal at most 1,000,000). Complex imports and embedded project files can take noticeable time.

HDRI loading accepts equirectangular HDR/EXR and supported ordinary images, decodes them off the main thread, converts to linear extended sRGB, and clamps negative converted channels to zero. Textured environments build a luminance-weighted lat-long sampling distribution with matching PDFs; small or high-contrast features may still require additional samples. The sampler's row/column search and PDFs are checked by a chi-square test. Procedural skies retain the sun-cone/cosine mixture proposals; the sun disc matches its sampled cone in every preset, and a sun below the horizon receives no proposals. Procedural textured walls, box sides and the ring place image row 0 at the top, so their textures are upright.

The scene browser also lists five small spectral scenes that are part of the app (**Included** filter): **Newton's Colour Series**, rows of spheres with soap films and anodized-titanium oxide films of increasing thickness, **Abbe Row**, a white slit seen through prisms of four optical glasses, whose spectra widen as the glass's Abbe number falls (its saved view **USD: Overview** shows where each slit stands relative to its prism), **Tyndall Tank**, a white beam that turns blue to the side and orange through a Rayleigh-scattering medium, **Lamp Spectra**, the same colours under five lamp spectra in haze, and **Lantern Arcade**, a colonnade at night lit by 416 lamps of different colour temperatures, which shows what **Render › Advanced › Light sampling › Light tree** does with many lights. They open at once, without a download, as new untitled projects. Thin film and dispersion render only in spectral light transport, the default; with **Render › Method › Light transport › RGB** the films and spectra disappear. See [Examples/Spectral](../Examples/Spectral/README.md).

For repeatable environment tests, run `python3 scripts/fetch_test_hdris.py` to download the CC0 Poly Haven selection documented in [Examples/HDRI](../Examples/HDRI/README.md). These maps remain local test data and are not bundled into the application.

**Render and Export…** (Export tab) uses a separate renderer at the requested dimensions and sample count, pauses the preview, and supports cancellation during rendering and denoising. **OIDN denoised** is the default source: it filters the converged linear HDR accumulation with progressively accumulated primary-surface guides and the configured quality. By default OIDN chooses its own HDR input scale. The optional **Robust HDR input scale** setting (Render › Advanced) instead keys exposure on the lit, non-emissive surfaces. The diffuse-only isolated-firefly filter (**Diffuse firefly suppression**, on by default) addresses false bright regions without altering raw samples and can be cancelled. **Raw** and **MetalFX display** remain selectable. MetalFX output is a display estimate, not radiometric data: measured MetalFX/raw region means range from 1.03 on diffuse Cornell surfaces to 0.69 on reflective regions. Use the raw or OIDN source with OpenEXR when you need linear radiance. **Denoise Current Frame** (Render › Denoising, or the Render menu) needs the Beauty view mode. It freezes the current samples, filters them in the background, and displays the result directly in the viewport. Camera gestures are locked meanwhile, and preview capture then saves that view. **Clear Denoised Preview** acts only while a preview is shown and restores the prior paused/running state, which re-denoising also keeps. The OIDN memory check covers its own buffers and the live render frames. PNG applies display adjustments after denoising and is sRGB-encoded. OpenEXR stores the selected source's linear HDR radiance as 32-bit float RGB (no alpha), without exposure or tone mapping, so values above 65504 are kept. Both encoders preserve top-left orientation and write atomically. Output dimensions range from 16 to 8192 per axis; large sizes depend on available GPU and system memory. The memory check includes the MetalFX denoiser's internal buffers, measured once per device. The **Raw / MetalFX divider** is for preview comparison and is omitted from full-resolution exports.
