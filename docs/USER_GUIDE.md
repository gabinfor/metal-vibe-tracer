# User guide

## Inspector and navigation

Use **Inspector** to show/hide the scrollable sidebar. The window can shrink to 700×440. The inspector contains six editing pages. Settings opens separately from the toolbar or the application menu (⌘,). Settings, ⌘E, the Export… button and viewport picks reveal the inspector if it is hidden. The window title shows the project name (or Untitled). Errors also remain as a status-bar indicator after the status text changes; click it to read the full message.

- **Render:** ReSTIR Direct + First-Bounce GI, MIS, NEE, and BSDF strategies; MetalFX and OIDN preview; beauty, albedo, world-normal, log-depth, and material/roughness viewport modes; exposure, white balance, tone maps, and a raw/MetalFX divider. ReSTIR resamples primary direct lighting and the first diffuse indirect vertex; deeper diffuse, glossy, and transmission paths continue through the path tracer.
- **Camera:** presets, numeric position/target and FOV, aperture radius, focus distance, and named saved views. Drag to orbit, Shift-drag to pan, scroll to zoom. A press becomes a drag only after the pointer moves 3 points; a plain click selects the surface's material/object group without editing the camera or marking the document edited. Trackpads zoom with precise deltas; notched mouse wheels are scaled 10× per line. Numeric camera fields refresh after mouse navigation and accept positions and targets within ±1,000,000 and focus distances from 0.0001 to 1,000,000. Aperture zero is the original pinhole camera.
- **Lighting:** sky presets, sun direction/intensity, HDRI loading/rotation/brightness, finite-light color/intensity/size, and the existing fog preview. Sky/HDRI lighting applies to Pavilion and Mesh Studio; finite-light controls apply to Cornell, Veach, and Ring scenes. Veach's four emitters share the light controls.
- **Materials & Textures:** scene-aware object/group selection, OpenPBR presets, tint, roughness, metalness, coat, anisotropy, fuzz, IOR, transmission, normal strength, UV repeat/offset/rotation, image previews, scalar-map channel selection, and portable material presets. Numeric fields and sliders include per-property reset buttons. Numeric fields accept the system locale's decimal separator and surrounding whitespace; invalid text reverts to the previous value. A colour-panel drag records one undo step.
- **Objects:** imported hierarchy, rename/reparent, shared mesh instances, per-node visibility/transforms, deletion, OBJ append, frame selection/all, and **Remove unused materials**. Deleting objects keeps materials that are no longer assigned, until you remove them with that button. Procedural objects retain visibility, translation, XYZ rotation, uniform scale, and transform reset. Transforms pivot around the scene origin. Architecture and Cornell room surfaces are grouped; finite emitters use Lighting controls.
- **Project & Export:** New/Open/Save/Save As, independent output dimensions, export sample count, OIDN offline/raw/MetalFX source choice, PNG, HDR OpenEXR, and current-preview PNG capture.
- **Settings:** sample/time limits, preview scale, path depth, OIDN quality/guides/noisy-guide/HDR-scale/firefly controls, and the experimental ring boost. Limits of zero mean unlimited. The time limit counts only time the Mac is awake. OIDN and viewport display changes preserve raw samples. **Path depth** (formerly Scattering depth) counts path vertices as pbrt does: 1 is direct lighting only, 2 adds one bounce, and so on. Depth 1 used to render like depth 2. The inspector is top-aligned for quick access on short pages.

Keyboard shortcuts: Cmd-O opens, Cmd-S saves, Shift-Cmd-S saves as, Cmd-Z/Shift-Cmd-Z undo/redo, Cmd-P pauses/resumes, Cmd-R restarts accumulation, Cmd-E opens export controls, Cmd-F/Shift-Cmd-F frame the selection/all imported objects, and Cmd-W, Cmd-M and Cmd-H close, minimize and hide the window. The Window menu lists the standard window commands. Changes to exposure, white balance, comparison, and tone mapping preserve raw accumulated samples, and repaint immediately even while paused, complete, or showing an OIDN preview, without tracing new samples. Resizing or toggling the inspector while paused keeps the paused render. Switching between beauty and the inspection views preserves the beauty samples, including ReSTIR history. MetalFX operates at the internal render resolution, is available with ReSTIR on supported GPUs, and maintains its own temporal history. A paused refresh never re-runs MetalFX. The viewport and PNG export use the exact sRGB curve.

## Projects and materials

`.vtrace` projects embed texture bytes, the environment image, mesh assets, stable scene-node/material IDs, parent transforms, face bindings, MaterialX expression programs, per-scene state, camera, render controls, and saved views. They do not depend on original asset paths. Projects are saved in format 3: embedded images, the environment and meshes are stored once each, in an asset table inside the file keyed by SHA-256 content hashes, and mesh triangles are stored as binary data. Version 1 and 2 projects remain readable and are saved as format 3; a version 1 project's single imported mesh migrates when another OBJ is appended. Builds from before format 3 cannot open format-3 projects. `.vmat` presets use the same format. Version and value validation runs before loading, and failed asset decoding preserves the active project. `.vmat` presets carry one material, including its MaterialX program/images when present, or manual maps and UV/channel settings. Undo/Redo restores project edits (up to 40 actions); render samples and pause state are not project edits. Undoing a display-only or camera-only edit keeps the accumulated samples and the OIDN preview. Undoing Open also restores the previous file association, so the next Save cannot overwrite the opened file. Failed operations add no undo step.

Changes autosave after a one-second debounce (five seconds for camera-only changes) and on normal quit to `~/Library/Application Support/VibeTracer/Autosave.vtrace`. Pending autosaves coalesce to the newest snapshot, and an unchanged revision is not rewritten. An autosave keeps its images and meshes as separate files in `~/Library/Application Support/VibeTracer/AutosaveAssets/`, named by their SHA-256 hash and written once, so a new revision writes the small `Autosave.vtrace` plus only payloads not stored yet. After each successful write, stored payloads that no recovery file references are deleted once they are more than ten minutes old. Recovery copies (`Autosave-previous.vtrace`, `Autosave-unrestorable-<date>.vtrace`) need that folder beside them: to move one elsewhere, copy `AutosaveAssets` along with it, or open it and use Save As, which writes a self-contained project. Quit waits for pending autosaves and explicit saves, then flushes the final state; a failed final write offers Cancel Quit. The last autosave is restored on startup with its project file association and edited state. An autosave that cannot be restored is moved aside as `Autosave-unrestorable-<date>.vtrace` and never overwritten. Explicit project saves are atomic and remain separate from the recovery file.

Open, New and Open USD Scene ask **Save / Don't Save / Cancel** when the document has unsaved changes. With Don't Save, the replaced document is kept only as the recovery copy `Autosave-previous.vtrace`. While a project opens or saves, other project commands, inspector popups and camera gestures are unavailable. Undo, redo, scene switches and imports prepare their resources off the main thread and reuse unchanged GPU resources.

Projects hold at most 512 MiB of embedded images (maps, MaterialX images and the environment) across all scenes, with identical images counted once, and a project file is limited to about 1.3 GiB. Save refuses a project that would exceed what Open accepts and explains what to reduce.

Base-color images decode as sRGB and multiply tint; 16-bit and grayscale images decode correctly, and gray images sample as gray in every channel. Roughness and metalness maps use linear data and replace scalar values; select R/G/B/A for packed maps. Tangent-space normals use +Y (green toward the image top) like MaterialX, remain linear, perturb the interpolated shading normal, and agree on both sides of a surface. **Clear** restores the scalar parameter's effect. Maps use repeat wrapping, mipmaps, and an approximate ray-cone footprint, and are evaluated at primary and secondary hits. UV repeat/offset/rotation and normal strength can be edited independently.

**Original scene material** preserves its original type while allowing maps. A roughness or metalness map promotes it to OpenPBR with scalars that match the inspector: a matte surface takes the inspector roughness, glass stays transmissive, and a mirror stays metallic. A mirror with only a roughness map keeps its legacy glossy lobe and takes the map's roughness. Editing surface parameters or tint also creates a custom OpenPBR surface. Original ideal mirrors/glass otherwise retain their delta behavior; new rough surfaces have a roughness floor of 0.03. The finite-light colour well shows sRGB and stores linear light colour. Volumetric absorption, subsurface scattering, opacity, thin films, dispersion, UDIMs, and displacement remain outside the exposed material model.

## OpenUSD scenes

In **Objects**, choose **Open USD scene…** for `.usd`, `.usda`, `.usdc`, or `.usdz`. Import opens a complete scene, including supported lighting and cameras, and replaces the current imported content. It composes references, payloads, and selected variants with the official SDK at the stage’s start time. Cancel leaves the active scene intact. An import is stopped after five minutes; time the Mac spends asleep does not count. The report lists fallbacks and unsupported features and remains available in Objects. Save as `.vtrace` to embed meshes, material images, matrices, lights, and the report for portable reopening; Undo restores the previous project.

Supported: polygon meshes (including concave faces), indexed UV0/normals, material face subsets, hierarchy, shared mesh assets, nonuniform/mirrored transforms, stage units/up-axis, visibility, perspective cameras as saved views, rectangular, disk and sphere area lights (disks and spheres as equal-area polygons), one textured or constant-color dome, and one distant light. The distant light is an independent sun with its authored angle. Its brightness follows the UsdLux definition: an unnormalized light's irradiance is intensity × 2^exposure × π·sin²(angle/2), so a default unnormalized sun is dimmer than in earlier versions. Degenerate faces are dropped and placeholder meshes skipped, with report lines. A camera's focus distance is used only when authored; otherwise the orbit pivot is the first surface on the view ray. Opening a USD scene starts an untitled document without the previous project's saved views. PreviewSurface’s metallic workflow and supported direct MaterialX UsdShade nodes map to the existing bounded OpenPBR evaluator. Area-light radiance is editable in Materials. Original imported matrices are retained beneath the inspector’s local transform adjustments.

This is snapshot import, not full USD round-trip editing. Subdivision uses control cages; point instancers, skinned animation, volumes/curves, arbitrary shader networks, USD export, and external `.mtlx` Sdf composition are not implemented. OCIO/ACES color management, camera roll/lens shift, and some light features are not represented. The importer reports approximations; PreviewSurface-to-OpenPBR shading is not an exact BSDF match. Existing limits remain 256 nodes, 56 imported materials and 500,000 rendered triangles. See [OpenUSD coverage and reference scenes](../Examples/OpenUSD/README.md).

## MaterialX materials

A small walkthrough is included in [Examples/MaterialX](../Examples/MaterialX/README.md).

In **Materials**, use **Import MaterialX…** to load a self-contained `.mtlx` document. On an imported mesh, supported materials enter the scene library and the first is assigned to the selected face subset. On a procedural surface, the first supported material replaces that slot. The import report lists rejected materials and ignored look assignments. Select a mesh child to change its subset bindings; edits to a shared material affect every assignment.

This is a bounded local importer/evaluator, not the MaterialX SDK or a visual node editor. It accepts 1.38/1.39 XML and the `open_pbr_surface` model. Supported nodes are `constant`, `texcoord` (UV0), `image`, `multiply`, `add`, `subtract`, `mix`, `clamp`, scalar `extract`, `normalmap`, `rotate2d` (constant degrees), and matching-width/scalar-broadcast `convert`. Nodegraph outputs and interface inputs resolve into the same program. Authored constants and default surface inputs are editable in the inspector; graph structure remains imported. Reset buttons restore the persisted imported default. Graph parameters use linear values.

Images use local paths at import, then embed their bytes. Images must be regular files of at most 128 MiB (1 GiB per document); paths outside the document's folder are accepted but reported, because the image is embedded. Documents must be UTF-8 or ASCII XML of at most 16 MB, and syntax errors report their line and column. Supported color spaces are linear/lin_rec709/raw/none and srgb/srgb_texture; a colorspace applies only to color3/color4 images and is ignored, with a report line, on float and vector images. `rotate2d` follows MaterialX 1.39: a positive angle rotates clockwise, the opposite of earlier versions. Images use periodic addressing and linear/mipmap filtering. UV arithmetic can tile/offset coordinates; `place2d`, additional UV sets, UDIMs, procedural noise, custom definitions, XInclude, OCIO transforms, and look assignment rules are unsupported. Missing images and unsupported connected nodes reject the affected material. Each material supports up to 64 instructions, with 128 graph images total.

Mapped OpenPBR inputs are base color/weight/metalness, specular roughness/weight/IOR/anisotropy, coat weight/roughness, fuzz weight, transmission weight, and surface normal. The renderer retains its roughness floor (0.03), IOR range (1.01–2.5), and 0–1 color/weight limits. Other authored surface inputs must be recognized default values: subsurface color/radius/radius scale/scatter anisotropy at their specification defaults and valueless `geometry_tangent`, `geometry_coat_normal` and `geometry_coat_tangent` (their geometric defaults) are accepted. `normalmap` accepts tangent space and rejects object space. Non-default subsurface, emission, opacity, dispersion, thin-film, and volume features are rejected. No `.mtlx` graph export is implemented. `REFERENCES.md` documents the implementation and adaptations.

## Meshes, environments, and export

**Import OBJ** reads positions, optional UVs/normals (including one-component `vt u` lines), positive and negative indices, backslash line continuations, and convex polygon faces (fan triangulation). Only numerically collinear faces are skipped, and their count is reported; errors name the line. OBJ import is prepared off the main thread and fails early if it would exceed 256 scene nodes. Missing normals use face normals. A median-split CPU BVH accelerates triangle intersections inside the existing Metal tracer, including shadows, reflections, transmission, picking, and denoiser guide rays. The triangle test is watertight, so rays aimed at shared edges and vertices do not slip between triangles. Import opens Mesh Studio, appends assets, and frames the new import. `o` and `g` become parent/mesh nodes; `usemtl` creates face subsets with named materials. Select a mesh in Objects or click it in the viewport, then choose a subset and material in Materials. Instances share geometry and initially share materials; assignments can be changed per instance. Parent visibility is inherited, and reparenting preserves local transform values. MTL shading, curves, vertex colors, and animation are not imported. Triangulate concave polygons before import. Limits are 256 scene nodes, 56 imported materials plus eight procedural slots, and 500,000 triangles across instances. The initial GPU bridge flattens visible instances and rebuilds the BVH after edits; complex imports and embedded project files can take noticeable time.

HDRI loading accepts equirectangular HDR/EXR and supported ordinary images, decodes them off the main thread, converts to linear extended sRGB, and clamps negative converted channels to zero. Textured environments build a luminance-weighted lat-long sampling distribution with matching PDFs; small or high-contrast features may still require additional samples. The sampler's row/column search and PDFs are checked by a chi-square test. Procedural skies retain the sun-cone/cosine mixture proposals; the sun disc now matches its sampled cone in every preset, and a sun below the horizon receives no proposals. Procedural textured walls, box sides and the ring now place image row 0 at the top, so textures that previously appeared upside down are upright.

For repeatable environment tests, run `python3 scripts/fetch_test_hdris.py` to download the CC0 Poly Haven selection documented in [Examples/HDRI](../Examples/HDRI/README.md). These maps remain local test data and are not bundled into the application.

**Render and export** uses a separate renderer at the requested dimensions and sample count, pauses the preview, and supports cancellation during rendering and denoising. OIDN offline is the default source: it filters the converged linear HDR accumulation with progressively accumulated primary-surface guides and the configured quality. By default OIDN chooses its own HDR input scale. The optional **Robust HDR input scale** setting instead keys exposure on the lit, non-emissive surfaces. The diffuse-only isolated-firefly filter addresses false bright regions without altering raw samples and can be cancelled. Raw accumulation and the MetalFX display remain selectable. MetalFX output is a display estimate, not radiometric data: measured MetalFX/raw region means range from 1.03 on diffuse Cornell surfaces to 0.69 on reflective regions. Use the raw or OIDN source with OpenEXR when you need linear radiance. **OIDN Preview Current Frame** on the Render page needs the Beauty viewport. It freezes the current samples, filters them in the background, and displays the result directly in the viewport. Camera gestures are locked meanwhile, and preview capture then saves that view. **Clear OIDN Preview** acts only while a preview is shown and restores the prior paused/running state, which re-denoising also keeps. The OIDN memory check covers its own buffers and the live render frames. PNG applies display adjustments after denoising and is sRGB-encoded. OpenEXR stores the selected source's linear HDR radiance as 32-bit float RGB (no alpha), without exposure or tone mapping, so values above 65504 are kept. Both encoders preserve top-left orientation and write atomically. Output dimensions range from 16 to 8192 per axis; large sizes depend on available GPU and system memory. The memory check includes the MetalFX denoiser's internal buffers, measured once per device. The divider is for preview comparison and is omitted from full-resolution exports.
