## Rendering and sampling

### RESTIR2020 — Direct-light reservoir reuse

Benedikt Bitterli, Chris Wyman, Matt Pharr, Peter Shirley, Aaron Lefohn, and Wojciech Jarosz. **Spatiotemporal Reservoir Resampling for Real-time Ray Tracing with Dynamic Direct Lighting.** *ACM Transactions on Graphics* 39(4), Article 148, 17 pages, 2020. [Author publication page](https://research.nvidia.com/labs/rtr/publication/bitterli2020spatiotemporal/). [DOI: 10.1145/3386569.3392481](https://doi.org/10.1145/3386569.3392481).

**Used in:** `restir_temporal_kernel`, `shading_kernel`, and direct-light reservoir target/weight evaluation. This project adapts ReSTIR DI for primary diffuse surfaces, with temporal and spatial reuse, history rejection, and capped history counts. It does not reproduce the paper's full unbiased estimator or incorporate NVIDIA's RTXDI SDK.

**2026-09-26 adaptations:** both passes seed per pixel so that they share one lens sample; `decorrelate_shading_seed` then rehashes the shading-pass seed, so spatial-neighbour offsets no longer reuse the temporal pass's candidate draws. Temporal reuse and reprojection now also run while the camera moves: `Uniforms.reservoirHistory` counts consecutive ReSTIR frames (camera moves keep it; scene cuts and resets clear it), and `Uniforms.reservoirHistoryReset` skips temporal reuse on the first frame after only the reservoirs were reallocated. `restir_temporal_kernel` writes the resolved primary hit into the per-pixel `PrimarySurface` cache (`PathTracerRenderer.primarySurfaceStride`, 104 B/pixel); `shading_kernel` and `metalfx_guides_kernel` read it instead of re-tracing and re-resolving the primary ray.

**ReSTIR PT (2026-09-29):** DI reuse is unchanged under `IndirectReuse.restirGI` and `.restirPT`; unified ReSTIR PT (`.restirPTUnified`, `RESTIRPTE2026` Sec. 6.1) samples direct light as two-vertex paths of its own reservoirs, so no DI pass runs and the DI textures are placeholders. The `PrimarySurface` cache is now 128 B per pixel: it also stores the primary ray direction (`PrimarySurface.view`), from which ReSTIR PT shifts paths into a pixel.

**Unbiased combination (2026-09-29):** in compatibility mode (`COMPATRESTIR2026`), `shading_kernel` normalizes spatially combined DI reservoirs with the paper's Algorithm 6 (1/Z; checked against the author PDF on 2026-09-29): Z adds the confidence M of every reused reservoir, including empty ones (W = 0), whose pixel's target can be nonzero at the selected sample (`restir_di_in_support`). The test is local and geometric (the sample lies above the neighbour's G-buffer shading normal). It does not test the neighbour's albedo, geometric normal, view side or emitter facing, so a neighbour whose target is zero for one of those reasons is still counted (a small darkening). Uniform mode keeps the earlier combination unchanged: M sums only over neighbours that pass the binary test and hold a nonzero W, which excludes zero-valued reservoirs and biases the estimate upward (measured +0.5% on Cornell diffuse pixels at 320×240, +4% at 96×64; see `COMPATRESTIR2026`). The temporal pass keeps that exclusion in both modes.

**Stochastic pairwise MIS (2026-09-29):** with `SpatialNeighborSelection.stochasticPairwise`, `spmis_di_reuse` replaces the spatial loop and its normalization by `SPMIS2026`'s defensive pairwise MIS over a reuse cell, which is unbiased (spatial-only Cornell +0.026 ± 0.010% against uniform mode's +6.1%). Temporal reuse keeps its bias status.

**Reservoir splatting (2026-09-29):** with `TemporalReuse.splatting`, `splat_temporal_kernel` runs the same temporal merge (`restir_di_merge`) while the view changes, with the history reservoir chosen by forward splatting, including occluded deep-layer domains (`HONG2026`); the merge keeps its bias status. Reprojection (`restir_backproject`, `restir_same_surface`) remains the default and the backup for splat holes.

### RESTIRGI2021 — First-indirect-bounce path reuse

Yaobin Ouyang, Shiqiu Liu, Markus Kettunen, Matt Pharr, and Jacopo Pantaleoni. **ReSTIR GI: Path Resampling for Real-Time Path Tracing.** *Computer Graphics Forum* 40(8), pp. 17–29, High-Performance Graphics 2021. [Official NVIDIA publication page](https://research.nvidia.com/publication/2021-06_restir-gi-path-resampling-real-time-path-tracing). [DOI: 10.1111/cgf.14378](https://doi.org/10.1111/cgf.14378).

**Used in:** `gi_geometry`, `eval_restir_gi_target`, `gi_connection_visible`, the GI reservoir textures, GI candidate/temporal reuse in `restir_temporal_kernel`, and spatial reuse/reconnection in `shading_kernel`. For a diffuse primary hit `x1`, the local subset samples one diffuse `x2`, estimates outgoing radiance there with one direct-light sample and complementary MIS, converts the primary BSDF proposal from solid angle to area measure, and temporally/spatially reuses the `x2` path suffix. Reconnection re-evaluates the current primary BSDF, geometry term, scalar RGB target, and visibility. The ordinary tracer supplies deeper diffuse, glossy, and transmission paths.

**Visibility correction (2026-09-08):** `gi_connection_visible` recomputes its direction from the offset origin to the stored secondary point, keeping the traced ray and endpoint distance consistent.

**Spatial neighbours (2026-09-29):** GI spatial reuse selects its neighbours independently of DI, uniformly or by `COMPATRESTIR2026`. In compatibility mode, GI spatial reuse also uses the `RESTIR2020` Algorithm 6 normalization. `restir_gi_in_support` counts neighbour q's M when the selected secondary vertex faces q (`gi_geometry` > 0) and q's reconnection passes the Jacobian bound.

**ReSTIR PT (2026-09-29):** this path is now `IndirectReuse.restirGI`, the automatic choice for the procedural scenes (scenes 0–5); imported scenes default to ReSTIR PT (`RESTIRPT2022`, `RESTIRPTE2026`). In the ReSTIR PT modes `restir_temporal_kernel` skips the GI candidate and its reservoir textures are 1 × 1 placeholders. `VIBE_INDIRECT_REUSE=gi` in `-D VIBE_TESTING` builds selects it everywhere. Measured against MIS at 320×240, it is biased by +0.25 ± 0.03% (Cornell) and +0.22 ± 0.08% (Cornell glass & mirror) of mean radiance.

**Adaptations and limits:** this is a bounded first-indirect-bounce diffuse subset, not the complete paper implementation. It omits glossy/specular shift mappings, full path reconnection, pairwise/generalized MIS, and reuse beyond `x2`; uses simple normal/depth/material compatibility; caps temporal history; and accepts the bias from correlated practical reuse. Standard MIS remains the reference strategy.

**Reconnection Jacobian (2026-09-26):** `restir_gi_jacobian` evaluates the solid-angle Jacobian of the paper's Equation 11 for reconnecting a source path `x1q → x2` at `x1r`. The area-measure target already applies it, so `restir_gi_accepts_shift` only rejects temporal and spatial shifts whose Jacobian lies outside [0.1, 10], mainly short contact-corner reconnections with heavy-tailed weights. This bound is a local choice; rejecting such shifts adds bias in exchange for bounded weights. `restir_gi_enabled` disables GI reuse when the path-depth budget allows no continuation (see `PBRT2023`). The paper's Equation 11 was checked against the author PDF on 2026-09-26.

**Stochastic pairwise MIS (2026-09-29):** with `SpatialNeighborSelection.stochasticPairwise`, `spmis_gi_reuse` resamples the spatial GI candidates with `SPMIS2026`'s pairwise MIS. There, the Jacobian bound of `restir_gi_accepts_shift` becomes a domain restriction that the canonical weight shares, together with x2's visibility and geometric-normal side from the neighbour, so spatial GI reuse becomes unbiased. The temporal merge still rejects out-of-bound shifts without MIS weights.

**Reservoir splatting (2026-09-29):** `restir_gi_merge` also serves `splat_temporal_kernel` (`HONG2026`); deep-layer domains get `restir_gi_initial` canonical samples and no spatial reuse.

### COMPATRESTIR2026 — Compatibility-guided spatial neighbour selection

Orion Junkins, Markus Kettunen, Daqi Lin, Ravi Ramamoorthi, and Chris Wyman. **Compatibility-Guided Neighbor Selection for ReSTIR.** *Proceedings of the ACM on Computer Graphics and Interactive Techniques* 9(4), Article 52, 16 pages, July 2026 (High-Performance Graphics 2026; Wolfgang Straßer Award, per the [HPG 2026 awards page](https://www.highperformancegraphics.org/2026/awards/)). [NVIDIA publication page](https://research.nvidia.com/labs/rtr/publication/junkins2026compatibility/), [author PDF](https://research.nvidia.com/labs/rtr/publication/junkins2026compatibility/junkins2026compatibility.pdf). [DOI: 10.1145/3820024](https://doi.org/10.1145/3820024). The full text was read from the author PDF on 2026-09-28. The paper is CC BY 4.0; no code or figures were copied.

**What the paper does:** it replaces `RESTIR2020`'s spatial neighbour selection (M uniform taps in a radius-R disk, with a binary normal/depth test that can reject every tap) with Algorithm 1. It takes K candidate taps from the disk and resamples M neighbours from them with weighted reservoir sampling, in proportion to a continuous G-buffer compatibility score (Eqs. 14–15):

h = exp(−‖x₁ − y₁‖ / s) · max(n_x · n_y, 0)^β, with s = √(Ω d² / π),

where d is the primary-hit distance, Ω = 0.05 sr and β = 8. It uses A-Chao for M = 1 and A-ES for M > 1. The search stops early once more than M candidates score above 0.5. Candidates follow an R2 sequence with a randomized start through the concentric map. The paper recommends 8 ≤ K ≤ 32 and 30 ≤ R ≤ 100 pixels at 1080p (Fast: K = 32, R = 30). Because the selection depends only on G-buffer values, it leaves GRIS unbiased when the resampling (MIS) weights are correct. The paper tried a material term and dropped it.

**Used in:** `SpatialNeighborSelection`, `PathTracerRenderer.spatialNeighbors`, `Uniforms.spatialNeighbors`, `restir_compatibility`, `concentric_disk`, `compat_candidate`, `select_compatible_neighbors`, `restir_di_in_support`, `restir_gi_in_support`, and the DI and GI spatial reuse loops of `shading_kernel`. `uniform_neighbor` and `restir2020_compatible` keep the earlier uniform selection.

**Default (2026-09-29):** `SpatialNeighborSelection.automatic` resolves to compatibility-guided selection when `sceneIndex == 6` renders an imported scene graph and to the uniform `RESTIR2020` selection for the procedural scenes, following the equal-time measurements in `tests/PERFORMANCE.md`. Explicit `.uniform` / `.compatibility` settings are kept as given.

**Implemented as in the paper:** Eqs. 14–15 with Ω = 0.05 and β = 8; the R2 plus concentric-map candidate taps; A-ES without replacement (its first rank is an A-Chao draw); early stopping above 0.5; K = 32.

**Adaptations:**

- M = 4 per reservoir type, matching the four uniform taps that DI and GI each drew before. The paper recommends M ≤ 3.
- R = 24 pixels, at preview resolutions of about 320–800 pixels wide, against the paper's 30 at 1080p.
- DI and GI select separate neighbour sets (two selections per pixel). One shared set was about 5% worse on Pavilion (64-frame MSE 0.303 vs 0.288).
- The selection runs inline in `shading_kernel`, not as a separate pass.
- The R2 sequence's random start is a random 2D offset (Cranley–Patterson rotation), and the 8,192 precomputed offsets are not used.
- A binary material term is kept: only diffuse primary hits hold reservoirs, so other pixels score zero. Off-screen taps, the pixel itself and misses also score zero.
- A candidate pixel already held in the reservoir is not inserted twice.
- The binary `RESTIR2020` test no longer applies in compatibility mode. `restir_gi_accepts_shift` (the Jacobian bound, `RESTIRGI2021`) still rejects GI shifts.

**Bias status:** the paper's unbiasedness argument assumes correct MIS weights, and this renderer's spatial combination used M/ΣM weights. With those weights, the continuous score (which admits neighbours that the binary test rejected) measured +1.1% on Cornell and −0.6% on the instanced patches, against +0.5% and +0.3% for uniform mode. Compatibility mode therefore also applies `RESTIR2020` Algorithm 6 (1/Z) to DI and GI spatial reuse, with the geometric support test described under `RESTIR2020`. Measured diffuse-pixel bias against MIS (320×240, 256 frames, relative, ± SE; uniform then compatibility): Pavilion +0.31 ± 0.06% vs +0.22 ± 0.06%, Pavilion close-up +0.44 ± 0.09% vs +0.24 ± 0.09%, coated floor +0.37 ± 0.08% vs +0.16 ± 0.07%, Cornell +0.54 ± 0.03% vs +0.27 ± 0.02%, Cornell glass +0.34 ± 0.14% vs +0.10 ± 0.14%, UV-sphere mesh +0.16 ± 0.02% vs +0.20 ± 0.01%, instanced patches +0.27 ± 0.03% vs −0.05 ± 0.02%. The remaining bias comes from the temporal pass (zero-weight exclusion, M cap), the GI Jacobian bound and the approximate support test. The whole ReSTIR path remains a practical, not an unbiased, estimator. Using the exact target at the neighbour (its full primary surface) instead of the geometric support test gave the same bias and MSE within noise, at 4–12% more frame time.

**Measured effect** (Apple M4, `tests/PERFORMANCE.md`): at equal sample count (64 accumulated frames, 320×240, against a 1,024-frame MIS reference), MSE falls by 40% on the imported UV-sphere mesh, 61% on the instanced bumpy patches and 7% on Cornell. Pavilion views and Cornell glass are within ±1%. Frame time rises by 3–26%. At equal time (assuming MSE ∝ 1/frames), compatibility mode wins on the two mesh fixtures (−28% and −51%) and loses 2–12% on the procedural scenes. The ASWF Shader Ball has no diffuse primary hits, so no ReSTIR reuse runs there and both modes render identically. MetalFX display error after 4 frames at 640×480 changed by −45% (Cornell) and +7% (Pavilion). On a 128×96 Cornell view, raw error fell by 18% but the MetalFX output did not improve; `tests/GPUChecks.swift` therefore runs its MetalFX error-ratio gate, which was calibrated there, on the uniform selection. A larger radius (R = 48, the paper's Balanced setting) removed that small-image effect but cost 4–11 points more frame time, with unchanged 640×480 MetalFX error.

**Selection:** compatibility mode is the default. `PathTracerRenderer.spatialNeighbors = .uniform`, or `VIBE_SPATIAL_NEIGHBORS=uniform` in `-D VIBE_TESTING` builds, restores the earlier path. With it, all six `tests/benchmark.py` scenarios gave mean radiance identical to `d5a449f`'s shaders at zero tolerance. Exports copy the interactive renderer's mode. Since 2026-09-29 the Render inspector exposes it (**Spatial neighbours**, `StudioController.restirModeControls`) and projects store it (`ProjectDocument.spatialNeighbors`, absent in older files, which open as `.automatic`); see "September 29 ReSTIR mode controls".

**ReSTIR PT (2026-09-29):** imported scenes now default to unified ReSTIR PT (`IndirectReuse.automatic`), which has no DI or GI spatial pass and takes its spatial neighbours from `RESTIRPTE2026`'s pairing textures. This selection therefore applies where ReSTIR DI or GI runs: `IndirectReuse.restirGI` (the procedural default, where `SpatialNeighborSelection.automatic` picks uniform taps) and the DI pass of `IndirectReuse.restirPT`. `tests/Fix_compat-neighbors.swift` pins ReSTIR GI.

**Related, not used:** NVIDIA's RTXDI SDK adds this selection to the Ultra mode of its ReSTIR PT ([ChangeLog](https://github.com/NVIDIA-RTX/RTXDI/blob/main/ChangeLog.md)). No RTXDI code is used. The vMF similarity of Tokuyoshi 2023, cited by the paper, is not implemented. The stochastic pairwise MIS of Hedstrom et al. 2026, also cited, is implemented as a separate selection (`SPMIS2026`), not combined with this score.

### SPMIS2026 — Stochastic pairwise MIS for large-kernel spatial reuse

Trevor Hedstrom, Markus Kettunen, Daqi Lin, Chris Wyman, and Tzu-Mao Li. **Stochastic Pairwise MIS for Unbiased Large-Kernel Reuse in Real-Time.** *Computer Graphics Forum* 45(2), 12 pages, 2026 (Eurographics 2026; open access, CC BY). [NVIDIA publication page](https://research.nvidia.com/labs/rtr/publication/hedstrom2026stochastic/), [author PDF](https://research.nvidia.com/labs/rtr/publication/hedstrom2026stochastic/hedstrom2026stochastic.pdf), [supplemental code (MiniSPMIS)](https://research.nvidia.com/labs/rtr/publication/hedstrom2026stochastic/hedstrom2026stochastic.zip). The paper was read in full from the author PDF on 2026-09-29, with no DOI printed in it. The supplemental MiniSPMIS code (Slang/C++, no license notice) was read to confirm the defensive pairwise formulas, the confidence scaling and the cell search. No code or figures were copied.

**What the paper does:** GRIS spatial reuse normally resamples a few random neighbours. The paper defines M candidate domains, a large screen-space kernel, and evaluates only Ñ of them. The stochastic resampling MIS weight m̃_i = K(i) / (Ñ P(i)) · m_i (Eq. 15) is an unbiased estimate of any deterministic MIS weight m_i (proved in Appendix B), for Ñ draws with replacement and any P(i) that is positive where m_i is. Because P may depend on the samples, neighbours are drawn in proportion to c_i p̂(X_i) W_i (Eq. 17), so reuse focuses on pixels holding contributing samples. It is specialized to defensive pairwise MIS (Eq. 11): Eq. 16 gives the non-canonical weights, and Eqs. 18–19 estimate the canonical weight's sum from Ñc uniform pixels. The non-canonical confidences (and c_Σ) are scaled by Ñ/M against pepper noise (Sec. 4.3). The candidates are screen-space cells (Sec. 5): 8 × 8 tiles split by a hash of object ID and quantized normal. A pixel picks one cell by 12-tap weighted reservoir sampling of cell confidence sums, over a disk that starts at 30 pixels and grows by 25% per tap (Sec. 5.1). GPU multimaps list the cell's pixels (Algorithm 1). Algorithm 2 then applies Ñc = 1 and Ñ = 3 with M ≤ 64. The paper evaluates this in ReSTIR PT at 1080p and finds the main gain in disocclusions.

**Used in:** `SpatialNeighborSelection.stochasticPairwise` (`Uniforms.spatialNeighbors` = 3), `PathTracerRenderer.SPMISKernels`, `spmisCells` / `spmisSlots` / `spmisChoices`, `spmisTile`, `spmisPTCandidates`, `FrameResourcePlan.spmisBytesPerPixel`, `SPMISPixel`, `SPMISSlot`, `SPMISChoice`, `SPMISShift`, `spmis_key`, `spmis_similar`, `spmis_cells_kernel`, `spmis_find_cell`, `spmis_select_kernel`, `spmis_draw`, `spmis_uniform_pixel`, `spmis_neighbor_weight`, `spmis_canonical_beta`, `spmis_canonical_share`, `restir_pt_spmis_shift_kernel`, `restir_pt_spmis_kernel`, `spmis_di_reuse`, `spmis_gi_reuse` and the DI/GI branch of `shading_kernel`.

**Implemented as in the paper:** Eqs. 15–19 with defensive pairwise MIS; P(i) ∝ c_i p̂(X_i) W_i (Eq. 17); the Ñ/M confidence scaling (Sec. 4.3); Ñc = 1 and Ñ = 3; the canonical estimate from a uniform pixel of the cell, including pixels without a sample; 8 × 8 tiles split into cells by object (here material slot) and a normal quantized as floor(2n) per component, with candidate cells limited to one quantization step; the 12-tap confidence-weighted cell search with 25% radius growth, starting from the pixel's own cell; the pixel itself is a candidate when its own cell is chosen. It applies to ReSTIR DI and ReSTIR GI spatial reuse (`shading_kernel`) and to ReSTIR PT, where it replaces the paired reuse of `RESTIRPTE2026`.

**Adaptations:**

- Cells are built per tile in threadgroup memory (`spmis_cells_kernel`, one 8 × 8 threadgroup per tile), not with GPU hash multimaps. Each cell stores in-cell prefix sums of c_i p̂(X_i) W_i, so a neighbour is drawn by inverse-CDF search with its exact probability. MiniSPMIS instead estimates 1/P from an 8-sample RIS inside the cell.
- A search tap's cell is accepted only when its own key is within one normal step of the centre's. MiniSPMIS clamps the tap's attributes and looks up the clamped key in that tile.
- The search radius starts at max(1, height/120) pixels (2 at 320 × 240, 9 at 1080p), not 30. At preview resolutions an 8 × 8 tile already spans a large part of the scene. On unified ReSTIR PT (320 × 240, 64 frames), radii 16 → 8 → 4 → 2 lowered equal-sample MSE: Cornell 1.54 → 1.46 → 1.40 → 1.36e-4, UV sphere 7.04 → 6.69 → 6.36 → 6.13e-4, Pavilion 0.255 → 0.252 → 0.250 → 0.246. Searching only the own cell lowered raw error further, but MetalFX error on the UV sphere rose by 82%: the correlation artifacts that the paper's search avoids.
- The search runs in its own pass (`spmis_select_kernel`) and chooses one cell per reservoir type (DI; GI or PT). Inside `shading_kernel`, its 12 dependent reads cost 20–40% of the frame.
- The ReSTIR PT shifts run in their own pass, one shift per thread (`restir_pt_spmis_shift_kernel`: shift 0 is canonical, 1–3 are neighbours), as the paired reuse separates its shifts. This cut the SPMIS frame time by 11–29% against one kernel doing four shifts per pixel. Shifts into or from the pixel itself are identities.
- ReSTIR DI: the shift is the identity on light samples. A domain's target is `eval_restir_target_pdf` at its cached primary surface (`PrimarySurface`, including its view direction). A neighbour's own target is its weight sum / (M W). DI candidates are light samples, drawn whether or not they are visible, so the unshadowed target is exact.
- ReSTIR GI: the area-measure reconnection has Jacobian 1. In the canonical weight, y's target from domain i is zero unless `restir_gi_accepts_shift` accepts, x2 lies above x1_i's geometric normal (`sample_bsdf` rejects other directions) and x2 is visible from x1_i. The visibility test costs one ray per pixel, because GI samples are traced and so always visible from their source. Without these support tests, the canonical weight counted domains that cannot produce y (−0.08% on Cornell, spatial-only).
- The output confidence of ReSTIR PT's spatial reuse is c_c + c_Σ (Ñ/M-scaled). MiniSPMIS writes (c_c + c_Σ)/(1 + Ñ); the paper does not specify it. DI and GI spatial results are not written back.
- Shading keeps ReSTIR PT's vector-valued resampling weights Σ m̃ F W |∂T/∂x| (`RESTIRPTE2026` Sec. 6.3).

**Bias status:** Spatial reuse by stochastic pairwise MIS is unbiased for ReSTIR DI, GI and PT, including the GI Jacobian bound. In pairwise MIS the bound restricts the shift's domain, and the canonical weight applies the same restriction, so it is no longer a biased rejection. It still bounds the weights. The earlier normalizations did not achieve this: uniform mode's M/ΣM excludes rejected and empty neighbours, and compatibility mode's 1/Z uses an approximate support test without visibility.

Mean radiance against MIS (320 × 240, relative ± tile-clustered SE) was measured spatial-only, with reservoir history cleared every frame so spatial reuse is the only reuse:

- ReSTIR GI, uniform: Cornell +6.12 ± 0.17%, UV sphere +1.05 ± 0.06%, glass +3.33 ± 0.13%
- ReSTIR GI, compatibility: Cornell −0.205 ± 0.012%
- ReSTIR GI, SPMIS: Cornell +0.026 ± 0.010%, UV sphere +0.015 ± 0.010%, glass +0.03 ± 0.07%, patches −0.000 ± 0.015%, Pavilion −0.05 ± 0.07%
- Unified ReSTIR PT, SPMIS: every scene within ±0.06% and 2 SE; paired reuse also agrees there

The whole ReSTIR GI pipeline stays biased, because its temporal pass still caps M without MIS weights and excludes zero-weight reservoirs. In full accumulation, SPMIS measured Cornell +0.27 ± 0.02%, UV sphere +0.11 ± 0.01%, glass +0.26 ± 0.08% and patches +0.16 ± 0.02%, against uniform's +0.25%, +0.09% and +0.23%. Compatibility mode's darkening partly cancels the temporal bias (Cornell +0.07%). Unified ReSTIR PT with SPMIS is unbiased within noise (Cornell +0.006 ± 0.010%, UV sphere +0.011 ± 0.008%, patches +0.005 ± 0.012%).

**Default (2026-09-29):** SPMIS is opt-in (**Spatial neighbours → Stochastic pairwise MIS**, `VIBE_SPATIAL_NEIGHBORS=stochastic` in `-D VIBE_TESTING` builds), and `.automatic` is unchanged:

- ReSTIR GI: it never wins. At equal samples it is −2% to +3% against uniform on the procedural scenes and trails compatibility-guided selection on the imported meshes, and it costs 5–21% more frame time.
- Unified ReSTIR PT, static accumulation: it lowers equal-sample MSE by 6–33% (tone-mapped 10–35%) for 13–55% more frame time. At equal time it wins only on the imported fixtures (Shader Ball −13%, UV sphere −11%, patches −4%) and loses 10–46% on the procedural views.
- Unified ReSTIR PT, moving camera: it lowers raw per-frame error by 10–20% (disoccluded pixels 11–49%) for 9–33% more frame time. The MetalFX display error does not improve (−1% to +23%; +4 to +23% on the meshes), because SPMIS spreads the same few samples over a cell.

Details are in `tests/PERFORMANCE.md`. Exports copy the setting.

**Spatio-temporal control variates (2026-09-29):** `RESTCV2026` is defined with deterministic pairwise MIS, so it is off with this selection (`ControlVariates.resolved`).

**Related, not used:** stratified reuse from several cells (the paper's future work), the combination with MCMC decorrelation, and roughness in the cell key (disabled in MiniSPMIS as well). Combined with reservoir splatting (`HONG2026`), SPMIS runs on the front layer only; that combination was not measured.

### RESTIRPT2022 — Generalized resampled importance sampling and ReSTIR PT

Daqi Lin, Markus Kettunen, Benedikt Bitterli, Jacopo Pantaleoni, Cem Yuksel, and Chris Wyman. **Generalized Resampled Importance Sampling: Foundations of ReSTIR.** *ACM Transactions on Graphics* 41(4), Article 75, 23 pages, 2022 (SIGGRAPH 2022). [NVIDIA publication page](https://research.nvidia.com/labs/rtr/publication/lin2022generalized/), [author PDF](https://d1qx31qr3h6wln.cloudfront.net/publications/sig22_GRIS.pdf). [DOI: 10.1145/3528223.3530158](https://doi.org/10.1145/3528223.3530158). The full text was read from the author PDF on 2026-09-29. The authors' Falcor prototype ([DQLin/ReSTIR_PT](https://github.com/DQLin/ReSTIR_PT), BSD-3-Clause) was read on 2026-09-29 to confirm how its pairwise and Talbot resampling MIS apply confidence weights; no code was copied.

**What the paper does:** GRIS generalizes RIS to correlated candidates from different domains, mapped into the target domain by bijective shift maps T with Jacobian |∂T/∂x| and weighted by resampling MIS weights (generalized Talbot, Eq. 36; generalized pairwise, Eqs. 37–38) with confidence weights (Sec. 6.2). ReSTIR PT (Secs. 7–8) resamples whole paths: a path tree traced from the primary hit is resampled into one path per pixel, whose reservoir keeps a random-replay seed and one precomputed reconnection vertex. The hybrid shift replays the base path's random numbers up to the vertex before the reconnection vertex x_k, then reconnects to x_k and reuses the stored suffix; x_k is the first vertex whose segment satisfies the connectability conditions (a distance threshold and a lobe roughness threshold of 0.2). Invertibility requires the offset path to agree on k. The real-time prototype uses one path tree per pixel, temporal reuse with generalized Talbot MIS and confidence cap 20, and spatial reuse from 3 neighbours in a 20-pixel radius with defensive pairwise MIS; ReSTIR DI supplies direct light.

**Used in:** `PTReservoir`, `pt_generate`, `pt_shift`, `pt_talbot`, `pt_pairwise`, `pt_accept`, `pt_seed`, `restir_pt_initial_kernel`, `restir_pt_temporal_kernel`, `restir_pt_shift_kernel`, `restir_pt_spatial_kernel`, `IndirectReuse.restirPT` and the primary-surface view direction (`PrimarySurface.view`).

**Implemented as in the paper:** GRIS resampling weights m p̂ W |∂T/∂x| over path reservoirs (F, W, confidence M); the hybrid shift in primary sample space with the Jacobian of Eq. 2 of `RESTIRPTE2026` (identity for replay); one precomputed reconnection vertex per path and the invertibility checks (the offset must fail the criteria at every earlier pair and pass them at x_k); separate integrands per path length and technique (NEE or BSDF-sampled emitter) with the renderer's own MIS weights, including the MIS-free suffix when k ≥ d − 1 so that the weight is re-evaluated after reconnection; generalized Talbot MIS with confidences for temporal reuse (c_Cap = 20); defensive pairwise MIS with confidences for spatial reuse, with shares 1/(n + 1) as in the prototype; the spatial output feeding the next frame's temporal reuse.

**Adaptations:**

- The path space is not lobe-indexed: vertices use the full (marginal) BSDF, as the path tracer does. Connectability therefore cannot use the sampled lobe's roughness; see the roughness guard under `RESTIRPTE2026`.
- The reconnection vertex is stored by position and re-found with a closest-hit ray from y_{k−1}, which also gives visibility and x_k's material from the new direction (its normal-map frame depends on the incoming direction). The prototype stores instance, primitive and barycentrics.
- BSDF-sampled segments are measured from the offset ray origin (`ray_origin`) in both the base path and the shift, so that the sampled direction, the traced distance and the reconnection describe the same segment. Measured from the surface point, identity shifts were off by 0.1–1%, and by 20% at short segments.
- Random numbers: every sampling event at path vertex j has its own stream (`pt_seed`), instead of one sequential sequence.
- A shift into an offset path whose count of non-delta continuations before x_k differs from the base path's is undefined when k ≤ d − 2, because the stored suffix bakes in MIS weights and the scattering budget (`scattering_limit`). This domain restriction is symmetric.
- Spatial neighbours come from the paired textures of `RESTIRPTE2026` with a symmetric G-buffer test (`pt_pair_compatible`: same material type, 10% depth, normals within 37°), not from uniform disk taps.
- Temporal reuse runs only while the view changes (`restir_pt_temporal`: the first frame of an accumulation, i.e. every frame while the camera moves). Over a static progressive accumulation, temporal reuse correlates frames; both papers recommend accumulating without it for converged images. `PathTracerRenderer.ptTemporalWhileAccumulating` restores the prototype's every-frame reuse. The temporal neighbour's domain is the previous frame's primary hit, read from a history copy of the `PrimarySurface` cache, with its view direction stored in the cache.
- The temporal same-surface test (the ReSTIR DI one) widens its distance bound to three pixel footprints at low resolutions.
- Path length is capped at 255 vertices (8-bit flags); roulette ends such chains long before.

**Related, not used:** the reconnection-only shift (the `RESTIRGI2021` subset remains as `IndirectReuse.restirGI`), offline multi-pass spatial reuse, and the 88-byte reservoir layout.

**Reservoir splatting (2026-09-29):** with `TemporalReuse.splatting`, `restir_pt_splat_temporal_kernel` applies the same Talbot merge (`pt_temporal_merge`) to front-layer pixels and deep-layer domains, whose temporal source is chosen by splatting (`HONG2026`); deep domains get `pt_generate` canonical paths and skip paired spatial reuse.

**Spatio-temporal control variates (2026-09-29):** `RESTCV2026` reuses the temporal Talbot weights and shifts for its difference estimate, and `pt_generate` also returns the path tree's unresampled estimate (Σ F / p(u) over its candidates) as the initial colour estimate. `PTReservoir` is unchanged.

### RESTCV2026 — Spatio-temporal control variates with ReSTIR

Zhong Shi, Cunhao Wu, Lifan Wu, and Kun Xu. **Spatio-Temporal Control Variates with ReSTIR for Real-Time Rendering.** *SIGGRAPH Conference Papers '26*, Los Angeles, July 19–23, 2026, 11 pages (Technical Paper Awards Honorable Mention). [Project page](https://hercier.github.io/restcv/), [author PDF](https://hercier.github.io/restcv/assets/pdfs/paper.pdf), [supplemental](https://hercier.github.io/restcv/assets/pdfs/supplemental.pdf), [authors' Falcor code](https://github.com/Hercier/ReSTCV). [DOI: 10.1145/3799902.3811113](https://doi.org/10.1145/3799902.3811113). The paper and the supplemental document (both CC BY 4.0) were read in full from the project-page PDFs on 2026-09-29. The authors' code (branch `restcv-release`: the ReSTIR PT base is BSD-3-Clause, their additions CC BY 4.0) was read to confirm the pairwise difference terms, the compositing weights and the initial estimate. No code or figures were copied, so `THIRD_PARTY_NOTICES.md` needs no entry.

**What the paper does:** ReSTIR shades a pixel from its one resampled sample, f(Y) W. The luminance target fits the intensity, but the colour follows the single selected path, which shows as colour noise. ReSTCV adds image-space control variates (Rousselle et al. 2016, below) to the reservoirs (Sec. 5). Each reservoir stores a colour estimate F_i of its pixel. It starts from the initial samples (Sec. 5.1.1) and is combined with the previous pixel's estimate in temporal reuse (Eq. 6) and with the neighbours' in spatial reuse (Eq. 8). Each reused estimate enters as a "from-j" estimator ⟨F_i⟩←j = α_ij ⟨F_j⟩ + ⟨F_i − α_ij F_j⟩ (Eq. 7). The difference term comes from the two reservoirs' own samples and the shifts ReSTIR already evaluates, weighted by the reuse's MIS weights (Eqs. 10–11), so it is unbiased and nearly free. α_ij = min(ρ_i / ρ_j, 2), with ρ the primary hit's average reflectance (Eq. 9). The compositing weights are the confidences M_j (capped at 20) and 1 for the initial estimate (Sec. 5.3). In spatial reuse the pixel's own estimate gets 1.6 times the weight, a value derived in supplemental Sec. 1. The pixel is then shaded with F_i instead of f(Y) W (Listing 1). The method is built on ReSTIR PT with pairwise MIS. A direct-lighting variant (supplemental Sec. 2) uses a proxy auxiliary function and a second level of control variates for ReSTIR DI.

**Used in:** `ControlVariates`, `PathTracerRenderer.controlVariates`, `activeControlVariates`, `resolvedControlVariates`, `defaultControlVariates`, `ptControls`, `ptControlStride`, `FrameResourcePlan.ptReservoirBytesPerPixel` and `splatBytesPerPixel`, `SplatPool.controls`, `ReSTIRModes.controlVariates`, `ProjectDocument.controlVariates`, `StudioController.controlVariateChoices` (**Path shading**), `restir_pt_control_variates` (`Uniforms.indirectReuse` bit 5), `PTControl`, `PT_CV_CENTER_WEIGHT`, `PT_CV_ALPHA_MAX`, `pt_encode_reflectance`, `pt_decode_reflectance`, `pt_reflectance`, `pt_cv_alpha`, `pt_accept` and `pt_generate` (the initial estimate), `pt_temporal_merge` (the temporal difference), `pt_cv_temporal`, `restir_pt_initial_kernel`, `restir_pt_temporal_kernel`, `restir_pt_spatial_kernel`, `restir_pt_deep_initial_kernel`, `restir_pt_splat_temporal_kernel`, the accumulation in `shading_kernel`, and the EXR clamp in `RenderImage.write`.

**Implemented as in the paper:** per-pixel colour estimates reused temporally and spatially through "from-j" estimators (Eqs. 6–8, Listing 1). The difference terms use the reservoir samples, the existing shifts and the reuse's own MIS weights (Eq. 10): generalized Talbot weights with confidences in temporal reuse, and the defensive pairwise weights of paired spatial reuse (canonical confidence c_c / n), exactly as resampling applies them. α_ij = min(ρ_i / ρ_j, 2) per channel (Eq. 9). Temporal compositing uses confidences, with q_init = 1 and M capped at 20. The pixel's own spatial weight is 1.6. Pixels are shaded from the estimate; the reservoirs and their resampling are unchanged. It applies to ReSTIR PT and unified ReSTIR PT with paired reuse, the paper's pairwise-MIS configuration.

**Adaptations:**

- Initial estimate: one path tree per pixel (`RESTIRPT2022`) supplies the candidates, so ⟨F_i⟩_init is the tree's unresampled estimate Σ F / p(u) over the candidates the RIS considers (`pt_accept`), as in the authors' code.
- Spatial compositing: each valid partner's estimator has weight one and the pixel's own 1.6, as in the authors' ReSTIR PT code, instead of the paper's M_j. With confidence weights, a disoccluded pixel (M = 1, partners with M ≈ 21) took almost its whole estimate from its partners. While orbiting, the per-frame error of newly disoccluded pixels then rose above resampled shading (Pavilion 2.74e-2 against 2.28e-2), and the patches' MetalFX error rose by 2.5%. Equal weights lowered both below resampled shading (Pavilion 2.23e-2, patches MetalFX −6%).
- Temporal α = 1, as in the authors' code; the temporal pair shows the same surface (`pt_same_surface`).
- ρ is estimated as the MetalFX albedo guides estimate it (`pt_reflectance`): the diffuse albedo plus a Fresnel specular term at the viewing angle. The paper integrates the BSDF with closed-form microfacet approximations (Haines and Akenine-Möller 2019, as the paper cites them). Dielectrics and ideal specular types keep α = 1. ρ is stored with 10 bits per channel on a square-root scale. On the measured fixtures α = 1 changed the orbiting error by under 0.5%, because paired pixels there share materials.
- Storage: the current estimate and ρ are a separate 16-byte `PTControl` per pixel rather than part of the 64-byte reservoir. The previous frame's final estimate stays in `ptIndirect` (the shaded result) until spatial reuse overwrites it, so no history copy is kept.
- Reservoir splatting (`HONG2026`): deep domains keep estimates in their pools (`SplatPool.controls`), and a destination takes its temporal control variate from its splat source, front-layer or deep. With front-layer estimates only, splatting lost its disocclusion gain under ReSTCV (tests/Fix_splatting.swift ratio 0.99–1.02 instead of 0.85–0.91).
- ReSTCV is off with stochastic pairwise MIS (`SPMIS2026`), whose stochastic weights the paper does not cover, and with ReSTIR GI.
- Negative values: a control-variate estimate can be negative in one frame (0.05–2.1% of the pixels while moving). The accumulation keeps them so that it converges without the clamp's bias (clamping each frame measured +0.02% to +0.09% of mean radiance on the patches). The frame MetalFX receives, the display, PNG and EXR exports, and OIDN's input clamp at zero.
- A non-finite estimator is dropped from the combination.

**Not implemented:** the direct-lighting variant of supplemental Sec. 2. Its proxy auxiliary function and second control-variate level assume an unbiased ReSTIR DI with pairwise MIS and visibility reuse; this renderer's ReSTIR DI (`RESTIR2020`) normalizes with M/ΣM or 1/Z and caps its temporal M. Under unified ReSTIR PT, the imported-scene default, direct light is part of the path reservoirs and gets ReSTCV. Also not implemented: multi-round spatial updates (supplemental Sec. 3.2; the paper's final method is single-step, as here), the STCV, decoupled-shading and constant-ratio ablation modes, and variance-aware compositing (the paper's future work).

**Bias status:** unbiased wherever ReSTIR PT is. Each "from-j" estimator adds α (⟨F_j⟩ − ⟨F_j⟩_pair), a zero-mean term: the reused estimate belongs to the domain that the difference shifts into, and the weights and α depend on geometry only. Mean radiance against MIS (320×240, 512 frames, relative ± tile-clustered SE, resampled then ReSTCV):

- Cornell: +0.005 / +0.004 ± 0.010%; with temporal reuse on every frame −0.011 / −0.021 ± 0.017%
- Cornell glass & mirror: +0.078 / +0.079 ± 0.072%; every frame −0.002 / +0.045 ± 0.097%
- UV sphere: +0.012 / +0.012 ± 0.008%; every frame −0.033 / −0.020 ± 0.012%
- Instanced patches: −0.002 / −0.001 ± 0.010%; every frame −0.001 / −0.010 ± 0.022%
- Pavilion: −0.074 / −0.073 ± 0.061%

The Talbot difference cancels between identical domains (4,759 of 4,760 Cornell pixels within 1e-3 in `tests/Fix_restcv.swift`). ReSTIR PT with ReSTIR DI keeps the DI pass's bias (patches −0.063% with or without ReSTCV).

**Default (2026-09-29):** `ControlVariates.automatic` resolves to ReSTCV wherever it applies: imported scenes (unified ReSTIR PT) and explicit ReSTIR PT. With unified ReSTIR PT and a moving camera it lowered the per-frame error by 5–47% and the MetalFX display error by 5–21%. It lowered static equal-sample MSE by 1–14%, for 0–3% more frame time: equal-time MSE is 4–12% lower on Cornell, the imported fixtures and the Shader Ball, and within ±1% on the Pavilion views and Cornell glass. Details are in "September 29 spatio-temporal control variates" and `tests/PERFORMANCE.md`. **Path shading → Resampled**, or `VIBE_CONTROL_VARIATES=off` in `-D VIBE_TESTING` builds, restores the earlier shading. With it, all `tests/benchmark.py` scenarios render mean radiance identical to `428d383`'s shaders at zero tolerance.

### HONG2026 — Multi-layer reservoir splatting

Pengpei Hong, Song Zhang, Daqi Lin, Markus Kettunen, Chris Wyman, and Cem Yuksel. **Multi-Layer Reservoir Splatting for Temporal Reuse under Disocclusion.** *SIGGRAPH Conference Papers '26*, Los Angeles, July 19–23, 2026, 10 pages. [NVIDIA publication page](https://research.nvidia.com/labs/rtr/publication/hong2026multilayer/), [author PDF](https://research.nvidia.com/labs/rtr/publication/hong2026multilayer/hong2026multilayer.pdf), [Utah project page](https://graphics.cs.utah.edu/research/projects/multi-layer-restir/). [DOI: 10.1145/3799902.3811232](https://doi.org/10.1145/3799902.3811232). The full text was read from the author PDF on 2026-09-29. The paper is CC BY 4.0; no code (none is published) or figures were copied.

**What the paper does:** it extends reservoir splatting (`LIU2025`) to several screen-space layers, so that a surface occluded in one frame keeps its reservoir and brings its history back when it is disoccluded. A reuse domain is a pixel-layer pair; layer i integrates paths whose first vertex is the i-th hit along the camera ray, with the primary visibility term removed (Eq. 3). To avoid tracing through every occluder, deeper layers are redefined by non-overlapping depth ranges around per-pixel representative hits (pixel-centre rays), [(1 − ε)t, (1 + ε)t] with ε = 0.01 and overlapping neighbours clamped at their midpoint (Eq. 4, Sec. 5): a splatted sample is tested for front-layer visibility and otherwise assigned the range holding its camera distance, with one visibility ray restricted to that range. Only active domains are kept (Sec. 4.3): every frame the representative hits of the previous active domains are splatted forward, the layer where an occluded one lands (counted by intersections along the ray to it) becomes active, domains within a 3-pixel radius are activated as hole filling without propagating further, and activations whose immediate occluder differs from the pixel's (instance IDs) are dropped. Active domains get canonical samples every frame; temporal resampling splats all active domains' samples into the current frame (and the canonical ones back for MIS); confidence follows `LIU2025` Sec. 4.3; spatial reuse runs on the front layer only; active domains are compacted; and only odd (front-facing) intersections define layers. It was evaluated in Falcor on an RTX 4090 at 1080p with 2–5 layers.

**Used in:** `TemporalReuse`, `PathTracerRenderer.temporalReuse`, `PathTracerRenderer.activeTemporalReuse`, `PathTracerRenderer.SplatPool`, `PathTracerRenderer.SplatKernels`, `splatCurrent` / `splatPrevious` / `splatMask` / `splatLayers` / `splatSources`, `splatCapacity`, `lastFrameSplatted`, `FrameResourcePlan.splatBytesPerPixel` / `reservoirSetBytesPerPixel`, `splat_frame` (`Uniforms.indirectReuse` bit 4), `SplatDomain`, `SplatLayers`, `SplatDI`, `SplatGI`, `splat_project`, `splat_half_width`, `splat_layer`, `splat_domain_useful`, `splat_activate_kernel`, `splat_layers_kernel`, `splat_deep_restir_kernel`, `restir_pt_deep_initial_kernel`, `splat_reservoirs_kernel`, `splat_source`, `splat_temporal_kernel`, `restir_pt_splat_temporal_kernel`, and the functions they share with reprojection: `DIReservoir` / `restir_di_initial` / `restir_di_merge` / `restir_di_encode`, `GIReservoir` / `restir_gi_initial` / `restir_gi_merge` / `restir_gi_encode`, `restir_same_surface`, `restir_backproject`, `pt_same_surface`, `pt_temporal_merge`.

**Implemented as in the paper:** multi-layer pixel-layer domains with deep layers defined by front-facing hits along the pixel's camera ray (the paper's odd intersections); depth ranges ε = 0.01 with midpoint clamping; transitive activation by splatting the previous domains' representative hits, with the layer counted along the ray towards the hit; hole filling whose domains do not propagate; the immediate-occluder test; canonical samples for every active deep domain (DI, GI and PT); temporal resampling for all domains, spatial reuse on the front layer only; a compacted domain pool; the whole scheme for ReSTIR DI, ReSTIR GI and ReSTIR PT / unified ReSTIR PT.

**Adaptations:**

- Domains stay point sampled: this renderer's reservoirs do not own their primary hit (they are not area reservoirs as in `LIU2025`), and the representative hit is the pixel's jittered primary ray (continued past the front layer), not a separate pixel-centre ray. A splat therefore does not preserve the sample's primary hit: `splat_reservoirs_kernel` chooses, per destination domain, the previous domain whose representative hit lands in its pixel, falls in its depth range and passes the temporal same-surface test of the active reuse (`restir_same_surface` for ReSTIR GI, `pt_same_surface` for ReSTIR PT), nearest in world space (a 64-bit atomic minimum of distance and source index). The existing merges then shift that domain's sample into the destination: the M-capped DI and GI merges of `RESTIR2020` / `RESTIRGI2021`, and `RESTIRPT2022`'s two-domain generalized Talbot MIS. Because the choice depends on G-buffer geometry only, not on samples, it is a neighbour selection; no visibility ray is needed for layer assignment, and there is no reverse splat of canonical samples or `LIU2025` confidence interpolation (each destination has one temporal source, whose confidence is used as in reprojection).
- A front-layer domain that no splat reaches (a splatting hole) reuses the reprojected pixel when it shows the same surface, i.e. the current reprojection (`LIU2025` Sec. 4.2 backup sample, used here only for holes).
- One deep layer (`SPLAT_DEEP_LAYERS` = 1, two layers in all), within the paper's 2–5: on the measured scenes a second deep layer did not lower the error measurably but doubled the pool on the instanced patches (+30% instead of +15% frame time while orbiting).
- Hole-filling radius 1 pixel (`SPLAT_FILL_RADIUS`) at preview resolutions of 320–800 pixels wide, against the paper's 3 at 1080p. On Pavilion, radius 0 kept 60–95% of the gain on newly disoccluded pixels and radius 3 gained no more than radius 1 with a 1.4× larger pool.
- Depth ranges are widened to twice the pixel footprint's depth extent on slanted surfaces (`splat_half_width`), because a same-surface splat can differ in depth by more than 1% within one low-resolution pixel.
- The immediate-occluder test compares material slots (`PrimarySurface.flags`), not instance IDs.
- The pool holds one domain per four pixels (`splatCapacity`); domains beyond it are dropped and counted, losing only their history. Deep domains keep reservoirs only where the active reuse has them (diffuse hits for ReSTIR GI).
- Splatting replaces reprojection only on frames where the view changed (the first frame of an accumulation) with valid history and a pinhole camera; static accumulations reproject as before and start the next moving frame with an empty pool. The paper does not support depth of field (Sec. 7).
- The scenes are static and only the camera moves, so the object-space transform of a hit is the identity.

**Bias status:** the source selection is geometric, so splatting adds no bias class of its own. Each merge keeps its reprojection status: ReSTIR DI and GI temporal merges remain biased (M cap without MIS weights, zero-weight exclusion, the GI Jacobian bound), and ReSTIR PT's Talbot merge is unbiased for the chosen pair. Deep domains receive canonical samples every frame, which the paper requires for unbiasedness. Per-frame mean radiance while moving agreed with MIS as well as reprojection did (alternating-view test in `tests/Fix_splatting.swift`; unified ReSTIR PT −0.7 ± 0.5% and +0.1 ± 0.4%, ReSTIR GI −0.5 ± 0.6% and +0.9 ± 0.4%, against −0.7 / +0.0% and +0.0 / +1.3% with reprojection).

**Measured effect and default (2026-09-29):** see "September 29 reservoir splatting" below and `tests/PERFORMANCE.md`. `TemporalReuse.automatic` resolves to reprojection in every mode; `PathTracerRenderer.temporalReuse = .splatting`, or `VIBE_TEMPORAL_REUSE=splatting` in `-D VIBE_TESTING` builds, enables it. Exports accumulate a static view, which never splats, so the export renderer uses reprojection and allocates no splat resources. The Render inspector exposes the setting (**Temporal reuse**) and projects store it (`ProjectDocument.temporalReuse`); see "September 29 ReSTIR mode controls" for persistence and precedence.

**Spatio-temporal control variates (2026-09-29):** with ReSTIR PT, deep domains also carry `RESTCV2026` colour estimates (`SplatPool.controls`; 16 B per slot and pool). `restir_pt_deep_initial_kernel` writes their initial estimates, and `restir_pt_splat_temporal_kernel` combines each domain's estimate with its splat source's.

**Related, not used:** NRD denoising and uniform (non-adaptive) k-layer domains. Stochastic pairwise MIS (`SPMIS2026`) can be selected together with splatting and then reuses spatially on the front layer only. The combination was not measured.

### LIU2025 — Reservoir splatting

Jeffrey Liu, Daqi Lin, Markus Kettunen, Chris Wyman, and Ravi Ramamoorthi. **Reservoir Splatting for Temporal Path Resampling and Motion Blur.** *SIGGRAPH Conference Papers '25*, Vancouver, August 10–14, 2025, 11 pages. [Author PDF](https://research.nvidia.com/labs/rtr/publication/liu2025splatting/liu2025splatting_paper.pdf), [authors' Falcor implementation](https://github.com/Jebbly/Reservoir-Splatting) (not read or used). [DOI: 10.1145/3721238.3730646](https://doi.org/10.1145/3721238.3730646). The paper (CC BY 4.0) was read from the author PDF on 2026-09-29 as the basis of `HONG2026`; no code was copied.

**What the paper does:** instead of backprojecting each current pixel into the previous frame, it forward-projects (splats) every previous-frame path by its object-space primary hit into the pixel it lands in, reconnects that hit to the new camera (a visibility test), and resamples it there with area (pixel-footprint) reservoirs, a reprojection Jacobian (Eqs. 14–16), a two-term generalized balance heuristic (Eqs. 11, 13; the canonical sample is reverse-splatted) and confidences interpolated from the backprojected pixel (Eq. 17); optional backup samples fill splat holes (Sec. 4.2); splatting at several times gives motion blur (Sec. 4.4).

**Used in:** `splat_project`, `splat_reservoirs_kernel` and `splat_source` (forward projection of previous domains into the pixel they land in, with atomics resolving several splats per pixel, and the backup sample for holes).

**Not implemented:** area reservoirs with sample-owned primary hits, the reprojection Jacobian and its MIS, reverse splats and interpolated confidences (see the `HONG2026` adaptations), multi-splatting and motion blur, and depth of field.

### PBRT2023 — Path tracing and sampling implementation reference

**Used in:** complementary light/BSDF weighting, throughput accounting, and compensated Russian roulette in `shading_kernel`; mathematical context for `frameJitter`. The local jitter is an unscrambled base-2/base-3 Halton sequence, centered on zero and repeated every 1,024 samples, rather than pbrt's full sampler. Excluding ideal reflection/refraction chains from the scattering budget and choosing separate roulette survival ceilings are local adaptations, not pbrt's termination policy. Finite path depth and approximate ReSTIR reuse still limit claims of unbiasedness for the whole renderer.

**Path depth (2026-09-26):** the Settings control is now **Path depth** (formerly "Scattering depth"), carried in `Uniforms.cameraTarget.w`. `scattering_limit` derives every depth decision from it, following the `maxDepth` convention of pbrt's `PathIntegrator` (section 13.4), where the depth test precedes direct-light sampling: depth 1 is direct lighting only, and each non-delta continuation consumes one event while the last vertex still receives NEE. `restir_gi_enabled` and `restir_gi_has_complementary_bsdf` use the same budget. BSDF-only sampling includes the emission reached by its final permitted continuation. Before this change depth 1 behaved like depth 2.

**Studio extensions:** `lens_ray` uses a uniform circular aperture and a focus plane perpendicular to camera forward. G-buffer and shading passes reuse the same per-pixel lens sample; MetalFX guides recover that sample's lens origin. This is a thin-lens approximation, not a multi-element optical model. `OBJMesh.hierarchy` and the resource-aware `trace_scene` overload implement a local median BVH with a bounded traversal stack; since the 2026-09-28 acceleration change this flat BVH is the reference path (`MeshAcceleration.flat`), and imported meshes default to the two-level structure of `WALD2007`, `WIDEBVH2008` and `METALRT`. Its instances follow pbrt's object instancing ([section 7.1.2, Object Instancing and Primitives in Motion](https://pbr-book.org/4ed/Primitives_and_Intersection_Acceleration/Primitive_Interface_and_Geometric_Primitives), checked 2026-09-28): rays are transformed into each instance's object space with the parameter t unchanged (`instance_ray`), and hits are resolved on the world-space triangle (`instance_triangle`), as `SceneGraph.forEachRenderTriangle` flattens it. Since 2026-09-28, `OBJMesh.buildInPlace` permutes the shared GPU triangle buffer into BVH order in place, so no reordered host copy is made; `OBJMesh.build`, which returns a reordered copy, remains for tests. They do not copy pbrt code or implement its SAH builder. Also since 2026-09-28, `intersect_mesh_triangle` implements the watertight ray–triangle algorithm of `WOOP2013`, which pbrt-v4 also uses ([section 6.5.3](https://pbr-book.org/4ed/Shapes/Triangle_Meshes), with its rounding analysis in section 6.8.4, Robust Triangle Intersections). The local adaptations are listed under `WOOP2013`. It replaced a Möller–Trumbore-style determinant test with a relative cutoff, which was not watertight. Since 2026-09-26, `OBJMesh.hierarchy` stores each interior node's split axis in `links.z`, and `push_mesh_children` visits the child nearer along that axis first (the ray-direction-sign ordering described in section 7.3). `scene_occluded` is a separate any-hit visibility traversal: it stops at the first blocker before `tMax` and builds no hit attributes. Positive uniform-scale object transforms preserve ray distance, normals, and tangent frames through `object_ray`/`world_hit`.

`eval_environment` evaluates a rotated latitude/longitude image in linear RGB. For HDR maps, `MaterialLibrary.environmentImportance` builds a piecewise-constant distribution weighted by luminance × sin θ: a 1×H marginal row CDF and a W×H conditional column CDF (section A.5). `sample_direct_light` picks a texel with `environment_cdf_index`, whose `marginal` flag selects the axis explicitly so 1-pixel-wide maps work. It keeps the in-texel offset inside the chosen cell and uses that cell's density from `environment_cell_pdf`. `eval_environment_pdf` maps a direction to its texel through `environment_image_pdf`. Both densities include the spherical Jacobian `W·H / (2π² sin θ)`. Before 2026-09-26 the row search read texel (0,0) on every step, and the sampler re-derived the PDF from the direction, so about 1e-4 of samples used a neighbouring texel's density. `tests/Fix_lights.swift` now checks the sampler with a chi-square test on a non-uniform 64×32 map, compares sampled and evaluated PDFs, and runs a four-strategy furnace test.

Procedural skies keep the sun-cone/cosine mixture. `procedural_sun_one_minus_cos` gives each sky preset one sun-disc size, stored as 1 − cos of the half angle (8e-4, 7e-4 and 9e-4). `eval_procedural_sky`, the cone proposal in `sample_direct_light` and `environment_mixture_pdf` all use that size. `in_sun_cone` tests sin² through a cross product, because 1 − cos is below float resolution for sub-degree suns. `environment_sun_probability` returns zero, so no proposals go to the cone, when the sun is off, when an HDRI replaces the sky, or when the procedural sun is below the horizon. For the Veach sphere lights, `sphere_cone_one_minus_cos` evaluates 1 − cos θmax as `x / (1 + √(1 − x))` with `x = r²/d²`. This is an algebraic identity that avoids the cancellation pbrt's section 6.2.4 handles with a small-angle branch. It is a local form, not pbrt's code.

Since 2026-09-28 the imported emitter list (`sample_direct_light`, `imported_emitter_area_pdf`) also holds MaterialX emitters, selected by area × a host-estimated weight stored in `emissions[slot].w` while their radiance is evaluated per sample; see `MATERIALX` (graph-driven emission) for why the estimator stays unbiased.

**Z sampler (2026-10-02):** [section 8.7.6, Blue Noise Sobol' Sampler](https://pbr-book.org/4ed/Sampling_and_Reconstruction/Sobol_Samplers) (`ZSobolSampler`, read 2026-09-29) is the implementation reference for `z_shuffle` (the 24-permutation base-4 digit shuffle chosen by a hash of the higher digits and the dimension) and for `z_owen` (the `FastOwenScrambler` constants); see `ZPP2026` for the adaptations.

**ReSTIR PT and mirror chains (2026-09-29):** `pt_generate` uses the same scattering budget, MIS weights and roulette policy as `shading_kernel`, but applies roulette at initial sampling only and records it in the PSS source density (`RESTIRPTE2026` Sec. 6.2.4). `sample_bsdf` now renormalizes ideal reflections (dielectric and mirror): in long chains rounding compounded into non-unit rays, which the sphere test (written for unit directions) then hit off the surface; a path trapped in the Pavilion chrome sphere grew a 400-unit direction and a 1e13 radiance sample. Primary diffuse ReSTIR DI estimates the full direct integral, so its BSDF emitter-hit contribution is excluded; conventional NEE vertices use complementary power-heuristic weights through `emission_weight`. The previous unconditional ReSTIR BSDF weight double-counted direct lighting and was reverted on 2026-09-08. Finite-light size affects intersected geometry, proposal/evaluated PDFs, and reservoir geometry terms consistently. Scene-light color/intensity affect both visible emission and sampled emission. These controls reset accumulation and reuse history.

### WOOP2013 — Watertight ray/triangle intersection

Sven Woop, Carsten Benthin, and Ingo Wald. **Watertight Ray/Triangle Intersection.** *Journal of Computer Graphics Techniques* 2(1), pp. 65–82, 2013; published June 28, 2013, updated July 9, 2013. [Paper page and PDF](https://jcgt.org/published/0002/01/05/). The author PDF was checked on 2026-09-28. The same algorithm is described in `PBRT2023` sections 6.5.3 and 6.8.4.

**Used in:** `WatertightRay`, `watertight_ray`, `watertight_edge` and `intersect_mesh_triangle` for imported-mesh triangles, and `MeshBoxRay`, `mesh_box_ray` and `mesh_node_hit` for the conservative BVH traversal. Both are called from the resource-aware `trace_scene` overload and from `scene_occluded`. Once per ray, `watertight_ray` makes the dominant direction axis z, swaps x and y when that component is negative so the winding is preserved, and computes the shear and scale constants (paper section 3). Each 2D edge function then depends only on the ray and that edge's two vertices. An edge value of zero counts as inside for both neighbouring triangles (section 3.1), so rays aimed at shared edges and vertices cannot pass between them. As in the paper, det = U + V + W = 0 (a ray in the triangle's plane, or a degenerate triangle) is a miss. The test is two-sided and accepts t in [tMin, tMax). Hit points are still rebuilt from barycentrics, with the `mesh_hit_error` bound (see "September 26 audit remediation").

**Adaptations:**

- The permutation and shear are folded into three row vectors applied to each translated vertex: e_kx − S_x·e_kz, e_ky − S_y·e_kz and S_z·e_kz. Their zero and unit entries are exact, so this matches the paper's per-vertex transform without per-triangle index permutation.
- `watertight_edge` evaluates p.x·q.y − p.y·q.x under `#pragma METAL fp contract(off)`. The renderer compiles with relaxed math (`METALMATH`), which lets the compiler contract a product and a subtraction into an FMA ([Metal Shading Language Specification 4.1](https://developer.apple.com/metal/Metal-Shading-Language-Specification.pdf), section 1.6.3, dated 2026-06-04, checked 2026-09-28). Contraction would stop neighbouring triangles' values for a shared edge from being exact negatives, and in local tests it reopened cracks.
- Metal has no double precision. When the two rounded products are equal, their exact FMA rounding errors decide the sign instead of the paper's double-precision recomputation (section 3.2). Like the paper's fallback, this restores accuracy; the single-precision test is already watertight.
- World-space bounding (section 3.3): the paper enlarges each box by per-axis bounds of 5ε(|K − P| + max|K_z − P_z|), with ε = 2^-24, and adjusts reciprocal directions by one ulp. `mesh_box_ray` instead computes one scalar per ray from the BVH root, e = 20·2^-24·(max|origin| + max(|root.lo|, |root.hi|)). `mesh_node_hit` applies it to all three axes as shifted slab origins, lo − (o + e) and hi − (o − e), and divides by the direction. This local margin is twice the paper's bound, to cover the slab divisions as well. It is a pragmatic scene-wide choice, not the paper's per-axis derivation or a formal proof.

**Two-level traversal (2026-09-28):** the same test runs in each instance's object space (`blas_closest`, `blas_any`), with the per-ray box enlargement computed there from the object-space origin and the asset's bounds (`wide_ray`, `wide_node_hit`); a fixed object-space ray per instance keeps shared edges watertight. The top level grows its boxes by 2^-18 (1 + κ)(|origin| + reach), where κ is the largest transform condition number and reach bounds |translation| + ‖linear‖·|object coordinates| (`MeshSceneHeader.lo.w`/`hi.w`), so the rounding of the object-space ray cannot cull an instance. Occlusion slack and `HitRecord.error` add the transform's rounding (`instance_hit_error`); for identity instances both equal the former bounds and hits are bit-exact with the flat BVH. The hardware traversal (`METALRT`) replaces this test with Metal's and is gated on measured watertightness.

**Tests and cost:** `tests/Fix_renderer-followups.swift` casts 14,598 rays at shared edges and vertices of a curved patch. With the former test, 2,614 of them missed (as recorded in commit `9f80023`); none miss now, for closest-hit and any-hit traversal alike, and BVH traversal agrees with a brute-force loop. The test also checks edge-function antisymmetry and the tie fallback. In a paired benchmark against the previous shaders, the 8,130-triangle imported-mesh fixture costs about 1.2 ms (10%) more per 640×480 frame; see [tests/PERFORMANCE.md](tests/PERFORMANCE.md). No paper code is copied.

### ZPP2026 — Temporal and 3D Z sampling (Z++)

Abdalla G. M. Ahmed, Matt Pharr, and Hui Huang. **Z++: Temporal, Non-Uniform, and 3D Z Sampling.** *ACM Transactions on Graphics* 45(6), Article 210, 14 pages, December 2026 (SIGGRAPH Asia 2026; CC BY 4.0). [NVIDIA publication page](https://research.nvidia.com/labs/rtr/publication/ahmed2026zpp/), [author PDF and supplemental](https://research.nvidia.com/labs/rtr/publication/ahmed2026z%2B%2B/z%2B%2B.pdf). [DOI: 10.1145/3842533](https://doi.org/10.1145/3842533). The paper and its supplemental document were read in full from the NVIDIA PDFs on 2026-09-29. The O2m3 listing (Fig. 15) was transcribed and checked rather than copied blindly: the extracted text carries a stray figure label inside one mask constant (`10x0FFF000F`, read as `0x0FFF000F`), and with that reading every aligned block of 4^m points (m ≤ 6) is a (0, 2m, 3)-net with (0, 2m, 2) pairwise and (0, 2m, 1) axis projections, as the paper states (Python prototype, and `tests/Fix_zsampling.swift` up to 1,024 points with and without scrambling). Fig. 15 is a few lines of bit operations, reproduced as `z_o2m3_x/y/z`; the paper is CC BY 4.0, so this attribution suffices and `THIRD_PARTY_NOTICES.md` needs no entry.

**What the paper does:** Z sampling (`ZSAMPLING2020`) gives consecutive blocks of a low-discrepancy sequence to recursively shuffled Morton-ordered pixels, so each aligned 2^k × 2^k pixel block holds a stratified set and Monte Carlo error is dithered across pixels (Sec. 3; "Z noise", a shuffled ordered-dither mask). Sec. 4.1 extends it over frames: XOR-ing the frame index into the pixel's sequence number (Eq. 3, *PerPixel*) gives every pixel consecutive, ideally converging samples over time while each frame stays a Z mask; *TZ* interlaces the frame index (Eq. 5) and *STZ* also permutes the pixel index (Eq. 6) to trade per-pixel convergence for less block pixelation; *ReShuffle* shuffles independently per frame, with a high-dimensional sequence. Sec. 4.2 importance-samples tabulated maps by an equal-mass rectangle subdivision (ZEnv). Sec. 4.3 introduces O2m3, a binary 3D sequence whose every aligned 4^m block is a (0, 2m, 3)-net with optimal pairwise projections, in place of splitting a 3D constituent into a 1D and a 2D sequence; Fig. 15 evaluates it from the bit-reversed index with a few shift-XOR steps.

**Used in:** `Sampler`, `pixel_sampler`, `z_pixel_key`, `z_index`, `z_shuffle`, `z_owen`, `z_owen_seed`, `z_sobol1`, `z_o2m3_x`, `z_o2m3_y`, `z_o2m3_z`, `z_morton`, `z_float`, `z_dimension`, `rand_f` / `rand_f2` / `rand_f3` / `rand_decision` (both overloads), `sampler_event`, `sampler_candidate`, `sampler_joint`, the `Z_*` stream constants, `sampler_z`, `sampler_z_temporal` (`Uniforms.indirectReuse` bits 6–8), `pt_sampler`, `pt_initial_seed`, the templated consumers (`lens_ray`, `sample_cosine_hemisphere`, `sample_direct_light`, `sample_bsdf`, `pt_sample`, `restir_di_initial`, `restir_gi_initial`, `apply_camera_fog`, `sample_specular_manifold_caustic`), `restir_temporal_kernel`, `shading_kernel`, `restir_pt_initial_kernel`, `restir_pt_deep_initial_kernel`, `pt_generate`, `pt_shift`, `metalfx_guides_kernel`; host `SamplerMode`, `ZTemporal`, `PathTracerRenderer.sampler` / `zTemporal` / `activeSampler` / `resolvedSampler` / `defaultSampler` / `defaultZTemporal`, `ReSTIRModes.sampler`, `ProjectDocument.sampler`, `StudioController.samplerChoices` (**Sampler**).

**Implemented as in the paper:** Z-indexed padded constituents: each sampling decision draws from its own dimension, whose sequence index runs along the shuffled Z curve of the image; temporal Z sampling by XOR of a temporal index into the pixel index (Eq. 3), with the TZ interlacing (Eq. 5), STZ (Eq. 6) and a ReShuffle-like model selectable; O2m3 (Fig. 15) for the 3D constituents (light choice and point on the light; BSDF lobe choice and direction); 2D Sobol' and van der Corput points for 2D and 1D constituents; Owen scrambling of every coordinate.

**Adaptations:**

- *One key per pixel and frame.* The paper XORs the frame into the already shuffled pixel index of each constituent. Here the pixel index is shuffled once (`z_shuffle`, a recursive quadrant shuffle) and XOR-ed with the temporal index into a 32-bit key; each dimension's sequence index is a nested binary (Owen-type) scramble of that key (`z_index`). Both keep aligned blocks aligned, so frames stay Z masks and pixels accumulate nets. The key alone determines every number, so ReSTIR PT stores it as its random-replay seed (`pt_initial_seed`, `pt_sampler`), and replay is exact. It also couples two dimensions of a pixel over frames by a random nested permutation; with per-constituent padding, the paper's order would couple them by a fixed XOR (degenerate 2D projections of two 1D constituents over frames).
- *Progressive accumulation.* A still accumulation that began at sample s0 uses t = T(s0) XOR j at its frame j, so over its first 2^n frames every pixel holds one aligned block of 2^n samples in every model (a (0, n)-net per constituent, a (0, 6, 3)-net of O2m3 after 64 frames), wherever s0 falls. T is the identity (PerPixel), Eq. 5 (TZ, STZ) or a hash (ReShuffle-like: a fresh block, hence independent frames, while the camera moves; the paper's ReShuffle reshuffles with a high-dimensional sequence, which this renderer lacks).
- *Shuffle and scrambling cost.* The pixel shuffle follows PBRT2023's `ZSobolSampler::GetSampleIndex` (24 permutations of each base-4 digit chosen by a hash of the higher digits) over the low 12 digits, with permutations encoded as one of six quadrant-0-fixing permutations followed by a digit XOR and a 32-bit hash in place of MixBits. Per-dimension indices use the binary nested scramble above instead of a second quadrant shuffle (2.5× cheaper on the M4; the pixel shuffle already randomizes each node's child pairing). Coordinates use PBRT2023's FastOwenScrambler. The second Sobol' dimension is evaluated with a five-step GF(2) Taylor shift (a local derivation) instead of direction numbers.
- *Dimension allocation.* Events own 32 dimensions each, 16 events per path vertex (`sampler_event`): vertex 0 lens, fog and the spectral wavelength numbers (`Z_WAVELENGTH`, drawn since 2026-10-03); per vertex BSDF, NEE, roulette and caustic; ReSTIR DI candidates, ReSTIR GI's x1 BSDF and x2 NEE; ReSTIR PT's BSDF, NEE and roulette streams apart from the shading pass's, so the two passes never replay each other's draws (the role of `decorrelate_shading_seed`). The four ReSTIR DI candidates and unified ReSTIR PT's four light candidates are one consecutive block of four indices (`sampler_candidate`), so a pixel's candidates are stratified. Deep reservoir-splatting domains XOR their layer into key bits 26–28.
- *Resampling decisions stay random.* Reservoir updates, neighbour, pairing and cell choices draw from the PCG stream (`rand_decision`), seeded as before, so resampling stays independent of the candidates it selects and of neighbouring pixels' decisions. Deep splatting domains' DI/GI candidates also stay PCG (they are not replayed).
- *PCG fallback.* `SamplerMode.pcg` makes every draw continue the per-pixel PCG stream exactly as the earlier `thread uint &seed` code did: 3D draws are three consecutive draws in the old order, and conditional draws keep their condition (`sampler_joint`). `tests/benchmark.py` against `1124b00` renders identical mean radiance in every procedural scenario; the scene-6 scenarios differ from the baseline because the benchmark forces the baseline onto the flat BVH (`main` against itself shows the same differences).
- *Not implemented:* ZEnv non-uniform Z sampling (Sec. 4.2; the paper reports parity with pbrt's CDF sampler, and it would need its own replayable index stream), Q-ART base-4 scrambling, and pixel jitter as a Z dimension (camera jitter stays the shared per-frame Halton offset that MetalFX expects, `frameJitter`).

**Bias status:** unbiased wherever the PCG sampler is: every coordinate is Owen-scrambled, so each is marginally uniform, and ReSTIR's estimators are linear in samples whose marginals are unchanged (resampling decisions stay independent). Every accumulation is one of 256 Owen randomizations (`z_dimension` mixes the key's top 8 bits into each dimension's scrambles), so an image's mean error is correlated across its pixels but zero in expectation. Mean radiance against MIS over 6 independent accumulations agreed within 1–2 SE except the imported UV sphere under MIS (+0.029 ± 0.007%); see `tests/PERFORMANCE.md`.

### NILE2026 — Nested interleaving of low-dimensional elements (read; not implemented)

Abdalla G. M. Ahmed, Matt Pharr, Victor Ostromoukhov, and Hui Huang. **NILE: Nested Interleaving of Low-Dimensional Elements.** *ACM Transactions on Graphics* 45(1), Article 105, 15 pages, July 2026 (SIGGRAPH 2026; CC BY 4.0). [NVIDIA publication page](https://research.nvidia.com/labs/rtr/publication/ahmed2026nile/), [author PDF](https://research.nvidia.com/labs/rtr/publication/ahmed2026nile/nile.pdf). [DOI: 10.1145/3811283](https://doi.org/10.1145/3811283). Read in full from the NVIDIA PDF on 2026-09-29.

**What the paper does:** a meta-sampler. Low-dimensional "elements" (stratified via base-4 Owen scrambling, jittered grid, correlated multi-jitter, ART blue noise, dyadic netsets, and the nested (0, 2)-sequence "O2", which turns out to be 3D Sobol') each serve a modular sequence over power-of-two hierarchical intervals; a high-dimensional low-discrepancy sequence (SZ, Ahmed et al. 2025) indexes them so that their samples interleave uniformly in the joint space; Z-indexing distributes the result over pixels. It reports convergence comparable to global Sobol' and Z-indexed SZ, better behaviour on SZ's failure case, and no favouritism toward same-sampler references.

**Why not implemented:** its interleaving needs the SZ generator matrices and, for most elements, Q-ART / ART tables, constructions defined in other papers (SZ, TOG 2025; Q-ART, CGVC 2025) and not in NILE itself; the paper notes that its convergence "comes primarily from the high-dimensional LD sequence". This renderer's per-constituent padding has no such sequence, and ReSTIR resampling interrupts per-pixel joint structure after the first vertices. Z++'s O2m3 supersedes NILE's O2 element for 3D constituents (Z++ Fig. 14 embeds O2m3 under SZ for the same purpose). The Z++ sampler's per-event dimensions and its single key are the place where a high-dimensional orchestrating sequence could later be added.

OpenPBR inputs `subsurface_color`, `subsurface_radius`, `subsurface_radius_scale` and `subsurface_scatter_anisotropy` are accepted at their specification defaults. Valueless `geometry_tangent`, `geometry_coat_normal` and `geometry_coat_tangent` take their geometric defaults (`Tworld`/`Nworld`); authored values or other default geometric properties are rejected. `normalmap` accepts `space="tangent"` and rejects `object`.

Documents are bounded at 16 MB before parsing. Only UTF-8/ASCII encodings are accepted, which closes a DOCTYPE/ENTITY guard bypass through a declared UTF-7 encoding. XML syntax errors report line and column.
- **Shared images:** images shared by several shaders in one document are decoded and bound once. *(2026-09-28: project and preset files now also store them once, in the format-3 asset table, which closes R-74; see the remediation record.)*
- **Normal-map frame:** the MaterialX `normalmap` node and inspector normal maps share `tangent_space_normal`: +Y toward the image top, built on the interpolated shading normal, and consistent on both faces of a surface.

**Graph-driven emission (2026-09-28):** `MXCompiler.compile` accepts constant or connected OpenPBR `emission_luminance` and `emission_color` and emits one `multiply` register, `MaterialXProgram.emission` (`GraphHeader.info.w`; −1 when neither input is authored, so existing programs are unchanged). The semantics are those of the pinned [v1.39.5 `open_pbr_surface.mtlx`](https://github.com/AcademySoftwareFoundation/MaterialX/blob/v1.39.5/libraries/bxdf/open_pbr_surface.mtlx) (`emission_weight = emission_color × emission_luminance`, a `uniform_edf`, defaults 0 and (1, 1, 1)) and of the [OpenPBR 1.1.1 specification](https://academysoftwarefoundation.github.io/OpenPBR/) Emission section, both checked 2026-09-28: `emission_luminance` is a luminance in cd/m² (nits), `emission_color` is an unbounded multiplier (HDR textures allowed), and coat and fuzz absorb the emitted light. `resolve_materialx` writes the product to `Material.emission`, clamped to 0–1e8 and zeroed on back faces (the importer keeps `geometry_thin_walled` false). `openpbr_emission` applies the coat exactly as that graph does: `mix(uncoated, coated, coat_weight)`, where the coated EDF is the product × `coat_color` through a `generalized_schlick_edf` with `color0 = 1 − F0` of the coat IOR, `color90 = 0` and exponent 5, that is a factor (1 − F0)(1 − (1 − N·V)⁵) ([v1.39.5 `mx_generalized_schlick_edf.glsl`](https://github.com/AcademySoftwareFoundation/MaterialX/blob/v1.39.5/libraries/pbrlib/genglsl/mx_generalized_schlick_edf.glsl) and `mx_fresnel_schlick`). The importer fixes `coat_ior` at 1.6 and `coat_color` at white. The v1.39.5 graph does not attenuate emission by fuzz, so neither does this renderer, although the specification allows fuzz absorption. The Adobe `openpbr_compute_emission` was evaluated and not adopted: calling a second `prepare_openpbr` per emissive hit cost up to 6% of frame time in `tests/benchmark.py` even in scenes without emission, while the closed form is a few arithmetic operations. Emission is in the renderer's radiance units, the same scale as UsdLux intensities (`USDPREVIEW`). Surfaces that emit still scatter. `standard_surface` ([v1.39.5 `standard_surface.mtlx`](https://github.com/AcademySoftwareFoundation/MaterialX/blob/v1.39.5/libraries/bxdf/standard_surface.mtlx): `emission` × `emission_color`, coat-attenuated the same way) is not compiled, because the importer supports only `open_pbr_surface`.

*Estimator.* Graph emitters are true area lights for next-event estimation, with an unbiased MIS combination. `MaterialLibrary.rebuildArguments` places every triangle of a slot with positive `MaterialXProgram.emissionWeight` in the emitter list and stores that weight in `emissions[slot].w`, beside the luminance of constant emitters. The weight is a host estimate: the program's emission luminance evaluated with every image replaced by 1 and UV (0.5, 0.5). It shapes only the light-selection PDF (area × weight, `PBRT2023` 12.6 power sampling). The radiance is evaluated on the GPU for each light sample (`imported_graph_emission`, which rebuilds the hit attributes with `mesh_hit_attributes` at the sampled barycentrics and runs the same program) and at each BSDF hit, and both strategies use the same PDF (`imported_emitter_area_pdf`, `eval_light_pdf`) with the power heuristic (`MIS1995`), so a poor estimate costs noise, not bias. A slot whose estimate is zero is left out of the list, and `emission_weight` then gives its BSDF hits weight 1. Camera rays add the emission with weight 1. Light samples read images at the finest level; BSDF hits use the ray-cone level, so strongly minified emission textures differ by prefiltering between the two strategies. Graph emission on procedural scenes (slots 0–7) is BSDF-sampled only. Reused ReSTIR DI samples keep the radiance evaluated for their original receiver; that is exact for uncoated emission. `tests/Fix_shaderball-emission.swift` checks textured radiance at hits and at light samples against the texture × luminance, the coat factor, sampled against evaluated PDFs, and BSDF, light, MIS and ReSTIR-mode agreement on a graph-emissive quad.

*Image nodes.* Per the [v1.39.5 standard nodes](https://github.com/AcademySoftwareFoundation/MaterialX/blob/v1.39.5/documents/Specification/MaterialX.StandardNodes.md) `<image>` definition, a file reference that cannot be resolved yields the node's `default` input (zero when unauthored). An `image` without a file now compiles to that constant and is noted in the report, instead of rejecting the material. `uaddressmode`/`vaddressmode` `clamp` (coordinates clamped to 0–1 before sampling) is carried per axis in the image instruction (`value.z`/`value.w`) and sampled with a Metal clamp-to-edge sampler; `constant` and `mirror` are still rejected. `PrimarySurface` grew from 104 to 120 bytes to carry the primary hit's emission to the shading pass.

**Scene bridge:** `SceneGraph`, `MeshAsset`, `SceneNode`, and `SceneMaterial` use local stable IDs, parent transforms, shared mesh assets and face-subset bindings. `SceneGraph.worldTransform`/`forEachRenderTriangle` compose local transforms and transform normals with the inverse transpose; see `PBRT2023` [transformation background](https://pbr-book.org/4ed/Geometry_and_Transformations/Transformations). The GPU bridge currently flattens visible instances into a rebuilt median-split BVH. Since 2026-09-28, `MaterialLibrary.setMesh` sizes the shared GPU triangle buffer with `SceneGraph.renderTriangleCount`, streams `forEachRenderTriangle` straight into it, and puts it into BVH order in place (`OBJMesh.buildInPlace`), so the graph's assets are the only other host copy (R-101). Framing (`StudioController.frameMesh`) reads that buffer and uses the BVH root's bounds for the whole unrotated mesh. Also since 2026-09-28, `USDImporter.load` places its orbit pivots and default framing with `USDImporter.sceneExtent`: one streamed `forEachRenderTriangle` pass computes the bounds and, for every supported camera, the nearest hit along its view ray, so the import builds no flattened copy either. That pivot test stays the earlier two-sided Möller–Trumbore test, not `WOOP2013`: it only places the orbit target, a view ray that slips through a shared edge falls back to the bounds depth, and pivots and bounds stay bit-identical to the former flattened computation (`tests/Fix_usd-pivot.swift`). `SceneGraph.renderTriangles`, which returns a flattened copy, remains for tests. USD composition now occurs upstream in `OPENUSD`; this GPU representation remains a flattened BVH, not a two-level accelerator or native hardware instancing.

### USDPREVIEW — PreviewSurface and UsdLux adaptation

OpenUSD contributors. **UsdPreviewSurface Specification** and **UsdLuxRectLight**, 26.08 documentation, verified September 4, 2026. [Shading specification](https://openusd.org/release/spec_usdpreviewsurface.html), [rectangular lights](https://openusd.org/release/api/class_usd_lux_rect_light.html).

PreviewSurface shading is approximated by the existing OpenPBR BSDF; their lobes are not numerically identical. Since 2026-09-28 a connected or non-zero `emissiveColor` becomes OpenPBR `emission_color` at `emission_luminance` 1: the pinned MaterialX [v1.39.5 `usd_preview_surface.mtlx`](https://github.com/AcademySoftwareFoundation/MaterialX/blob/v1.39.5/libraries/bxdf/usd_preview_surface.mtlx) emits `uniform_edf(color = emissiveColor)`, which the renderer treats as radiance (see `MATERIALX` graph emission). Unlike that definition, a clearcoat attenuates the emission here. Unsupported opacity/displacement and specular workflow fall back with diagnostics. Textures are linear or sRGB; no OCIO/ACES pipeline is implemented.

`import_stage` converts rectangular lights into one-sided emitters. Disk lights become an equal-area eight-sided polygon, and sphere lights become an equal-area, outward-facing 80-face icosphere (`sphere_proxy`). Both are reported approximations; before 2026-09-26 spheres were a one-sided square. `SceneState.emissions`, `MaterialLibrary.rebuildArguments`, `trace_scene`, `sample_direct_light`, `eval_light_pdf`, `imported_geometry` and ReSTIR target evaluation integrate them into the existing tracer. Radiance maps from color × intensity × 2^exposure. Normalized lights divide it by the world-space area of the emitter actually built, so emitted power matches the authored light. Before, disks were divided by their bounding square, a 29% power loss. The schema's `normalize` wording ("dividing the luminance by the world-space surface area of the light") was checked on 2026-09-26. Radiance above 1e8 is scaled down and reported.

Emitter selection is power-weighted: the `emitters` buffer holds `[count, triangle indices, cumulative area × luminance, total]`, and `imported_emitter_area_pdf` gives a triangle's area density as luminance / total power, per the power light sampler of `PBRT2023` section 12.6. `imported_light_probability` gives the triangle proposal probability 1 when there is no environment or imported sun, and 0.5 otherwise. On a BSDF hit, `eval_light_pdf` reads the hit triangle from `HitRecord.triangle`. That makes it O(1), with no plane-tolerance search that double-counted emitters far from the origin. `PBRT2023` supplies the area-to-solid-angle Jacobian background.

A `UsdLux.DistantLight` becomes an independent directional sun (`StudioOptions.sunAngle`, `StudioOptions.independentSunCone` → `Uniforms.lens.w`, `independent_sun_radiance`, `environment_sun_probability`). It no longer depends on the environment intensity that USD import sets to zero, and it lights scenes that also have an HDRI. `USDImporter.load` stores its irradiance at normal incidence: `intensity × 2^exposure` when `normalize` is on, otherwise that value × sizeFactor, with sizeFactor = π·sin²θmax (θmax = angle/2) as the [UsdLux schema](https://github.com/PixarAnimationStudios/OpenUSD/blob/release/pxr/usd/usdLux/schema.usda) defines (checked 2026-09-26). An unnormalized default sun is therefore much dimmer than before: the new value follows the specification, and existing imports look different. The rendered angle is clamped to 0.1–90° at the same irradiance, and irradiance is clamped to 10,000; both clamps are reported. Tint is not applied.

Untextured domes become a constant-color lat-long environment (`constant_environment`). Non-lat-long dome formats, MeshLightAPI and VolumeLightAPI are skipped with a report line. `ND_image` inputs carry their colour space through `Usd.ColorSpaceAPI.ComputeColorSpaceName` ([UsdColorSpaceAPI](https://openusd.org/release/api/class_usd_color_space_a_p_i.html); attribute, then prim and ancestors). `srgb_texture`, `srgb_rec709_scene` and `sRGB` map to sRGB; `lin_rec709` and `lin_rec709_scene` map to linear; `raw`, `data` and `identity` map to raw. Other colour spaces make the material fall back with a report line. A `UsdPrimvarReader` `varname` connected to a material interface is resolved through `GetValueProducingAttributes` before the st-only check. A displayColor fallback is kept per prim colour.

The implementation is local code, not a copied USD renderer. Light textures, temperature, shaping, linking and filters are not evaluated. Dome transform and tint are omitted and reported. Finite-light, environment and distant-light sampled/evaluated PDFs and lighting are GPU-tested (`tests/USDChecks.swift`, `tests/Fix_lights.swift`, `tests/Fix_usd.swift`); light power and proxies are checked in `tests/USDChecks.py`. Ray offsets use the error bounds described under "September 26 audit remediation" rather than fixed offsets. No cross-engine radiometric equivalence is claimed.

### PETERS2019 — Bounded MESE for reflectance spectra

Christoph Peters, Sebastian Merzbach, Johannes Hanika, and Carsten Dachsbacher. **Using Moments to Represent Bounded Signals for Spectral Rendering.** *ACM Transactions on Graphics* 38(4), Article 136, 14 pages, 2019 (SIGGRAPH 2019). [Author page](https://momentsingraphics.de/Siggraph2019.html), [author PDF](https://momentsingraphics.de/Media/Siggraph2019/Peters2019-CompactSpectra.pdf), [supplementary code](https://momentsingraphics.de/Media/Siggraph2019/Peters2019-CompactSpectraCode.zip). [DOI: 10.1145/3306346.3322964](https://doi.org/10.1145/3306346.3322964). The paper was read from the author PDF on 2026-10-02, and its metadata was checked against the DOI record.

**What it provides:** the bounded maximum entropy spectral estimate. Trigonometric moments c of a signal in [0, 1] are mapped to exponential moments (Eqs. 6–7). Levinson's algorithm then gives C(γ)⁻¹e₀, and the Lagrange multipliers follow (Eq. 10). The reconstruction g(φ) = atan(Re λ0 + 2 Re Σ λl e^(−ilφ)) / π + 1/2 (Eq. 11) is smooth, bounded and matches all given moments (Theorem 5). Sec. 4.1 maps wavelengths to phases in [−π, 0] with a mirrored (even) signal, so the moments are real, and an optimized warp brings the warped Fourier basis close to the CIE CMFs.

**Implemented:** `lagrange3` and `moments_of_lagrange` in the generator, and `vibe_fourier_lagrange` and `vibe_fourier_reflectance` in the generated MSL include. This is the m = 2 (three real moments) closed form, written from Eqs. 6, 7, 10 and 11. The renderer uses it for every bounded colour (`spectral_lagrange`, `spectral_from_lagrange`, `spectral_reflectance`, `spectral_albedo`, `spectral_emission`, `prepare_bsdf`; on the host `SpectralColour.fourierLagrange`, a double-precision port for constant light colours), reconstructing ρ(λ_k) at a path's four warped phases (`Wavelengths.cosPhase`). The tests check moment reproduction to 2.4e-15 (Theorem 5), on the GPU in float32 against float64, and invalid-moment detection. The MSL uses `sinpi`/`cospi` for γ0′, for float32 accuracy near c0 = 1. The warp table comes from the authors' code (`Vendor/Spectral/Peters2019/XYZWarp.h`, BSD-3-Clause, notice in `THIRD_PARTY_NOTICES.md` and in the generated include). Everything else is a local implementation from the paper. The supplementary C++/HLSL/Python code was read for orientation, not copied.

### FOURIERSRGB2019 — Fourier sRGB and biasing

Christoph Peters, Sebastian Merzbach, Johannes Hanika, and Carsten Dachsbacher. **Spectral Rendering with the Bounded MESE and sRGB Data.** *Workshop on Material Appearance Modeling* (MAM 2019), H. Rushmeier and R. Klein (eds.), The Eurographics Association, pp. 1–5, 2019. [Author page](https://momentsingraphics.de/MAM2019.html), [author PDF](https://momentsingraphics.de/Media/MAM2019/Peters2019-SpectralRenderingMAM.pdf), [code](https://momentsingraphics.de/Media/MAM2019/Peters2019-SpectralRenderingMAMCode.zip). [DOI: 10.2312/mam.20191304](https://doi.org/10.2312/mam.20191304). The paper was read in full from the author PDF on 2026-10-02. This is the "Fourier sRGB" work cited by `PETERSBLOG2025`.

**What it provides:** a 256³ lookup from sRGB to three Fourier coefficients (Sec. 2.3, built there by nearest-neighbour search in CIELAB over a 1024³ sampling of moment space, under illuminant E), the Fourier XYZ / Fourier sRGB colour spaces for compressible coefficient textures (Sec. 3), and Levinson's algorithm with biasing (Appendix A, Alg. 2), which pulls invalid moment vectors back into the valid set (ε = 10⁻⁴, then 1).

**Implemented, with adaptations:** the renderer converts sRGB to moments at render time from the exactly solved 86³ grid (`FourierSRGB86.bin`, interpolated trilinearly in linear light: `spectral_moments`), with the cells it reproduces worse than 0.35 8-bit steps refined to exact solutions at every code (`spectral_refine_flags_kernel`, `spectral_refine_solve_kernel`, `PathTracerRenderer.refineSpectralGrid`). Measured over all 16,777,216 codes in the renderer's float32 path: max 0.459, mean 0.012 8-bit steps (`tests/Fix_spectral.swift`). The paper's 256³ lookup is kept as an opt-in test reference (`--lut256`): `FourierSRGB256.bin` maps 8-bit sRGB to (c0, c1, c2) in 3 × uint16. The construction of both differs from the paper's:

- Exact Levenberg–Marquardt solves in Lagrange-multiplier space, at 1 nm, on an 86³ grid. The moments follow by quadrature.
- Linear-light interpolation, with per-entry verification and exact re-solving of entries above 0.35 8-bit steps.
- Colours are defined under **D65** rather than E (white-balanced sRGB matrix, see `SRGB1999`), so that ρ ≡ 1 is sRGB white.

Measured: max 0.438 8-bit steps over all 16.7 M entries, ΔE76 ≤ 0.30. Storage is linear 16-bit moments, not Fourier sRGB. A local Fourier-sRGB-like encoding measured 0.83 steps at 10 bits and 2.5 at 8 bits, which is not exact, so the paper's matrix and gamma are not used. `vibe_fourier_lagrange` implements Alg. 2's biasing: c0 is clamped to [10⁻⁴, 1 − 10⁻⁴], and the generator clamps target channels to the same interval, which gives the 0.33-step floor at black.

### PETERSBLOG2025 — Spectral rendering blog series and reference path tracer

**What it describes:** Fourier sRGB reflectance with a 256³ lookup (part 1). Four wavelengths per path from one random number, λk = F⁻¹((u + k)/m), inspired by hero wavelength sampling (`HERO2014`). The BSD shader code was read to cross-check the algorithm structure only.

### HERO2014 — Hero wavelength spectral sampling

Alexander Wilkie, Sehera Nawaz, Marc Droske, Andrea Weidlich, and Johannes Hanika. **Hero Wavelength Spectral Sampling.** *Computer Graphics Forum* 33(4), pp. 123–131, 2014 (EGSR 2014). [Author PDF](https://jo.dreggn.org/home/2014_herowavelength.pdf). [DOI: 10.1111/cgf.12419](https://doi.org/10.1111/cgf.12419). The metadata was checked against the DOI record on 2026-10-02; the paper (Secs. 3–4) was read from the author PDF on 2026-10-03.

**What it provides:** several wavelengths per path, the first (the hero) sampled and the others placed at equal distances, all directional sampling driven by the hero (Sec. 3), the combined-density and spectral MIS view of the shifted techniques (Secs. 3.1–3.3, Eqs. 6–12), four wavelengths for SIMD (Sec. 3.4), dividing every wavelength's contribution by the probability that generated the path (Sec. 4.1), and keeping only the hero's channel through Dirac distributions that only it can follow (Sec. 4.1).

**Implemented, with adaptations:** the four stratified wavelengths of `PETERSBLOG2025` (equivalent to equidistant placement in the warped sampling domain). BSDF sampling at a vertex is driven by the upstream BSDF prepared at λ0..2 (`prepare_bsdf`), and every lane divides by that generating density (Sec. 4.1). At the first dispersive vertex a path keeps lane `hero` (chosen uniformly by the second `Z_WAVELENGTH` dimension), times four, for delta and rough dispersive interfaces alike (`spectral_arrive`, `Wavelengths.heroOnly`, `PT_RC_DISPERSIVE`; the upstream BSDF and `sample_bsdf` then refract at the hero's index, `openpbr_dispersion_adjusted_ior`). Choosing the hero uniformly among the stratified lanes keeps the estimator unbiased (checked: a vanishing dispersion leaves the image mean unchanged, `tests/Fix_spectral.swift`). **Not implemented:** the spectral MIS of Secs. 3.2–3.3, which would keep all four lanes through rough dispersive lobes.

### OIDN250 — Offline final-frame denoising

Intel Corporation. **Intel Open Image Denoise 2.5.0**, 2026. [Official source and API documentation](https://github.com/RenderKit/oidn), [official release](https://github.com/RenderKit/oidn/releases/tag/v2.5.0).

The checksum-pinned official macOS runtime is bundled without modification and loaded through OIDN's C99 ABI for final-frame processing. The local adapter copies the converged `rgba32Float` accumulation and configured primary-surface guides to an `RT` filter as `FLOAT3`, sets `hdr=true`, and writes the returned linear radiance into a new Metal texture. Fast, balanced, and high OIDN quality levels; color/albedo/normal guide selection; and the `cleanAux` noisy-guide hint are exposed. The texture can be displayed and captured in the viewport or passed to PNG/OpenEXR export. PNG display mapping occurs afterward; OpenEXR retains linear denoised values. Raw and MetalFX sources remain available.

**Adaptations and limits:** albedo and world-normal guides now use the same progressive jittered box reconstruction as beauty, avoiding a final-sample/accumulated-color mismatch. Default `cleanAux=false` tells OIDN that residual low-sample edge noise may remain. By default `inputScale` is left at OIDN's documented default of NaN, so OIDN computes the scale for HDR input itself. Per the OIDN README (reviewed 2026-09-26), NaN makes the scale be "computed implicitly for HDR images". OIDN's `core/autoexposure.h` uses a 0.18 key over a binned log-average luminance. The optional **Robust HDR input scale** setting (`OIDNOptions.robustInputScale`, off by default) instead sets `inputScale = 0.18 / exp(mean log L)` over sampled primary hits on non-emissive surfaces. Zero radiance is floored at 1e-4 × the brightest counted surface. This is a local analogue of OIDN's convention, not its code. It replaces the former default, 1/p99 luminance with a 1e-4 floor, which mis-exposed the input (R-40). Projects saved with the old option enabled now use the surface-keyed scale. A sampled 99th-percentile luminance remains only as the firefly-suppression threshold. Before filtering, an optional local test suppresses an isolated radiance outlier only when at least four neighboring pixels agree on diffuse material, normal, and albedo; this prevents a Monte Carlo firefly from becoming a broad false highlight and never changes raw accumulation. Both protections can be disabled in Settings. Reflected and transmitted geometry remains in radiance rather than the primary guides. Non-finite inputs become zero, radiance is nonnegative, albedo is clamped to 0–1, and normals are normalized. Cancellation uses OIDN's progress monitor. Since 2026-09-26 the firefly pass runs rows in parallel (`DispatchQueue.concurrentPerform`) with cancellation checks. `OIDNDenoiser.hostMemoryBytes`/`memoryError` preflight the adapter's own allocations before a preview or an OIDN export (`StudioController.startExport`): three RGBA32F readbacks with 256-byte-aligned rows (48 B/pixel), plus four FLOAT3 OIDN images, the luminance snapshot, the returned pixels and their result texture (84 B/pixel). That makes 132 B/pixel before row padding, plus a 512 MiB allowance for OIDN scratch memory, and resident render frames. The total is compared with half of physical memory. The former 84 B/pixel estimate was smaller than the adapter's own allocations (R-80). An OIDN preview requires the Beauty viewport, locks camera gestures while it runs, and restores the prior paused/running state when cleared or cancelled. OIDN's trained weights, device execution, and reconstruction are upstream behavior; the project does not implement or claim authorship of them. Exact archives, licenses, and dependency notices are recorded in `Vendor/OIDN/UPSTREAM.md` and the bundled `OIDN/doc` directory.

### OPENEXRLAYOUT — OpenEXR float export

Academy Software Foundation, OpenEXR project. **OpenEXR File Layout**, living documentation. [File layout](https://openexr.com/en/latest/OpenEXRFileLayout.html); ZIP predictor reference in [`OpenEXRCore/internal_zip.c`](https://github.com/AcademySoftwareFoundation/openexr/blob/main/src/lib/OpenEXRCore/internal_zip.c). P. Deutsch and J-L. Gailly, **ZLIB Compressed Data Format Specification version 3.3**, [RFC 1950](https://www.rfc-editor.org/rfc/rfc1950), 1996. Apple Inc., [`COMPRESSION_ZLIB`](https://developer.apple.com/documentation/compression/compression_zlib), living documentation, which produces raw DEFLATE (RFC 1951). Reviewed September 26, 2026.

**Used in:** `OpenEXRFloat.encode` and `OpenEXRFloat.zipChunk`, called by `RenderImage.write`. The encoder writes a single-part scanline file. It has the magic number 20000630, the eight required header attributes plus Rec. 709/D65 `chromaticities`, and alphabetically sorted `B`, `G`, `R` channels of type FLOAT (32-bit). It uses `ZIP_COMPRESSION` blocks of 16 scanlines, an offset table of 64-bit little-endian offsets, and increasing-Y line order. `zipChunk` applies OpenEXR's even/odd byte split and +128 delta predictor. It deflates with `compression_encode_buffer` and adds the RFC 1950 header and Adler-32 trailer, because `COMPRESSION_ZLIB` emits raw DEFLATE. It stores a block uncompressed when compression does not shrink it. There is no alpha channel. Values are linear extended sRGB (Rec. 709 primaries) as rendered. This is independent Swift code; no OpenEXR source is copied or linked.

### SHA256FIPS — Content-addressed project assets

National Institute of Standards and Technology. **FIPS 180-4, Secure Hash Standard (SHS).** August 2015. [Publication page](https://csrc.nist.gov/pubs/fips/180-4/upd1/final), [DOI: 10.6028/NIST.FIPS.180-4](https://doi.org/10.6028/NIST.FIPS.180-4). Apple Inc., [**CryptoKit `SHA256`**](https://developer.apple.com/documentation/cryptokit/sha256), living API documentation, also checked against the installed macOS SDK's CryptoKit interface. Both reviewed September 28, 2026.

**Used in:** `ProjectAssets.reference(for:)`, `ProjectAssets.load`, `ProjectAssets.reuseSidecar` and `ProjectDocument.writeAutosave`. Project format 3 (`ProjectAssets.formatVersion`) keys every embedded payload by `sha256:` plus 64 lowercase hex digits of its SHA-256 digest, computed with CryptoKit's `SHA256.hash(data:)`. These payloads are texture maps, MaterialX images, the environment image and mesh triangles. Identical payloads are therefore stored once. `.vtrace` files and `.vmat` presets keep each payload inline as base64 in the `assetTable`. Autosaves and recovery copies list only sizes and keep each payload as a binary sidecar in `AutosaveAssets/`, named by its digest and written once. `ProjectAssets.load` checks each payload against its digest, and `reuseSidecar` re-hashes an existing sidecar once per process, or after it changes, before referencing it. `ProjectAssets.collectSidecars` removes unreferenced sidecars older than `sidecarGracePeriod` (10 minutes) after a successful autosave write. The digest serves as an integrity check and content address, not as a security boundary. CryptoKit supplies the hash; the table layout, sidecar reuse and collection are local code.

### METALRT — Hardware ray tracing (default where watertight)

## September 29 ReSTIR mode controls

No new method: the Render inspector exposes the existing `IndirectReuse` (`RESTIRGI2021`, `RESTIRPT2022`, `RESTIRPTE2026`), `SpatialNeighborSelection` (`RESTIR2020`, `COMPATRESTIR2026`) and `TemporalReuse` (`HONG2026`, `LIU2025`) settings as **Indirect reuse**, **Spatial neighbours** and **Temporal reuse** (since the same day also `ControlVariates`, `RESTCV2026`, as **Path shading**) (`StudioController.restirModeControls`, enabled only with the ReSTIR strategy). - Persistence: `ProjectDocument.indirectReuse`, `spatialNeighbors` and `temporalReuse` store the raw values (`ReSTIRModes`); they are optional, so version 1/2 and earlier format 3 files decode without them and open as the default, and `validate()` rejects unknown values. - Memory: `StudioController.setReSTIRModes` preflights the change with `renderMemoryError(width:height:indirectReuse:temporalReuse:)` at the live render size; a mode that would exceed the budget (when the current one fits) is refused with `showError`, the popup reverts, and nothing else changes.
- Exports copy the project's indirect reuse and spatial neighbours. An export accumulates one still view, which renders identically with either temporal reuse (`tests/Fix_splatting.swift`), so the export renderer uses reprojection and allocates no splat resources; its OIDN preflight now passes the splatting state to `FrameResourcePlan`.
- The View and Render menus do not mirror these settings, as they do not mirror the sampling strategy.

### GI sampling endpoint correction — 2026-09-08

`sample_cosine_hemisphere` centers the radial draw in its 24-bit random bin before taking its square root. - `PBRT2023` (rounding error, [section 6.8](https://pbr-book.org/4ed/Shapes/Managing_Rounding_Error)): imported scenes rebuild mesh hit positions from barycentrics and record a per-hit bound, `HitRecord.error`. `mesh_hit_error` uses 2^-19 × the largest vertex coordinate magnitude, and `ray_hit_error` uses 2^-20 × (|origin| + t). `ray_origin` offsets along the geometric normal by max(error, `ray_epsilon`), and `endpoint_tolerance` bounds shadow and connection segment ends. The constants are local margins for relaxed math, not pbrt's `pError` propagation. The legacy procedural tolerances are unchanged, except that procedural primitives in graph mode no longer keep an absolute 1 mm `t_min` (R-51). A 20 µm triangle, sub-millimetre occluders and 1 cm emitters near the origin are covered by `tests/Fix_geometry.swift`. The earlier caveat that fixed ray offsets affect millimetre-scale geometry no longer applies.
- Shadow and connection rays use the bounded any-hit `scene_occluded` traversal with near-first child order (`PBRT2023`, section 7.3). Since 2026-09-28 it uses the same watertight triangle test and enlarged boxes as `trace_scene` (`WOOP2013`).
- Uniforms ABI: `reservoirHistoryReset` (offset 244) and `reservoirHistory` (offset 248) occupy former padding, with a 304-byte stride. `Uniforms.lens` is (aperture radius, focus distance, scene-graph mode, independent-sun 1 − cos); `uses_scene_graph`/`Uniforms.sceneGraphMode` read the third component. `tests/Fix_gpu-memory.swift` asserts host/shader struct sizes and offsets.
- Frame memory: `PathTracerRenderer.FrameResourcePlan` counts 120 B/pixel of frame textures, the 104 B/pixel `PrimarySurface` cache (120 B since the 2026-09-28 graph-emission change), 208 B/pixel of ReSTIR DI/GI reservoirs (ReSTIR only), 55 B/pixel of MetalFX textures, and the measured MetalFX scaler allocations (MetalFX only).
- Runtime resources: `runtimeResourceURL`/`runtimeRepositoryRoot` resolve shaders, the USD bridge and OIDN only from the app bundle. Test builds compiled with `-D VIBE_TESTING` may also use an explicit `VIBE_TRACER_REPOSITORY`. The launch working directory is never consulted. `scripts/check_bundle.py` validates a staged bundle, which `build.sh` swaps in only after it passes. `scripts/prepare_oidn.py` records a per-file SHA-256 table and the target architecture in `build/OIDN/VIBE_RUNTIME.json`, so existing caches are prepared once more. `scripts/buildsupport.py` marks `build/` with `com.apple.fileprovider.ignore#P` so that iCloud Drive keeps it local.

## September 28 acceleration structure

Imported meshes use a two-level structure (`Sources/Acceleration.swift`, `MeshSceneLayout`): each `MeshAsset` is stored once in object space with a 4-wide binned-SAH BLAS (`WALD2007`, `WIDEBVH2008`), and a TLAS bounds the visible `SceneNode` instances with their world transforms (`PBRT2023` object instancing). Where Metal's intersector passes the watertightness gate, the same layout is traced in hardware (`METALRT`); otherwise the software traversal (`WOOP2013` in object space) runs. The flat median BVH remains as the reference path (`MeshAcceleration.flat`, test seam `VIBE_ACCELERATION`). Changes that span entries:

- Buffers: the triangle buffer holds all assets' triangles (subset index in `uvc.z`), then their BLAS nodes, indexed relative to their asset so unchanged assets move as bytes; the node buffer holds `MeshSceneHeader`, `MeshInstanceRecord`s, the TLAS and the subset-to-slot table. A flat BVH leaves `nodes[0].lo.w` zero, which is how the shader tells the layouts apart (`mesh_two_level`). `HitRecord.triangle` and the emitter list use rendered-triangle IDs (an instance's first ID plus the asset-local index); `scene_triangle` and `MaterialLibrary.renderedTriangle` resolve them to the world triangle.
- Edits: transform and visibility edits rebuild only the TLAS and instance table (hardware: the instance structure); binding edits rewrite the slot table and keep the instance structure; geometry edits rebuild only assets whose triangles changed (`assetBuildCount`, `sceneBuildCount`).
- Limits: `SceneLimits.triangles` (stored triangles) is 1,000,000 and `SceneLimits.renderedTriangles` 64,000,000; instances are bounded by the 256 scene-graph nodes. The flat path keeps rendered = stored. Mesh buffers and acceleration structures count against `MaterialLibrary.meshBudget` and `PathTracerRenderer.renderMemoryError`.
- Shader cost: scenes 0–5 run kernels compiled with `VIBE_MESHES=0` (`PathTracerRenderer.proceduralKernels`), because the unused mesh code slowed them by 13–17%.
